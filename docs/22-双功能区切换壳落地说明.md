# 22 · 双功能区切换壳落地说明（v0.27）

## 一、这次做了什么

在**完整保留**原「智能自适应绕过系统」的前提下，把 HallucinationFix 幻觉文档作为**第二个大功能区**接入同一套前端演示控制台。本版只交付**导航壳**，用于验证「双功能区并列 + 顶栏切换」的导航结构是否顺手、信息架构是否清楚，不含任何后端、模型、数据库或训练逻辑。

用户已确认的落地意向：目标形态为**真实 C/S 系统**（FastAPI + Ollama + SQLite + LoRA 微调 + 双机局域网），但首版范围选择**仅切换壳**，先把导航结构立住，再把页面内容逐步填入。

## 三、关键设计取舍

1. **不动现有页面一行 HTML**。切换控件由 `core.js` 按 `.topbar` / `.site-head` 自动注入，覆盖全部 8 个现有页面；既省去逐页改动，也避免碰触状态机、Store、pendingRun 等已验证逻辑。
2. **既有主题体系零侵入**。功能页是浅亮 SOC 底（`--t-1` 深字），落地页是深墨底（`--ink` 浅字）。切换控件用 `color: inherit` 让文字随页面主题走，只有当前项用两边一致的酸柠实心，因此无需为任一主题写特例。
3. **禁用而非隐藏**。8 个规划入口全部渲染为 `disabled` + `aria-disabled="true"`，让人一眼看到第二功能区的完整版图与「尚未实现」的诚实边界，符合 unslop 的形状+文字双编码。
4. **零外联保持**。全部资源为本地相对路径；验收脚本用 DOM 查询确认 `script[src] / link[href] / img[src]` 无任何 `http(s)` 引用。

## 五、诚实边界

- 本版是**导航壳**，不是可运行系统：判定、归因、训练、评测、推理均未实现。
- 目标形态依赖双机局域网与 8GB 显存算力机，本演示环境不具备，指标数字为目标配置、非实测。
- 8 个入口当前不可点击，需按文档 §4/§5/§6/§7 逐步接入后端与前端后才会启用。
