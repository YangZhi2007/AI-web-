## 0. 一句话定位

两个静态 HTML，零依赖、零 CDN、零网络请求。主页讲"这是什么"，控制台讲"它怎么跑"。所有探测过程由本地**契约桩（MockEngine）**驱动，全部为演示数据。

## 3. 五分钟演示动线

### 主线（约 3 分钟）

1. **主页 · 第一屏**：黑底 + 两行压缩展示字「闭环自适应 / 与绕过判定」，右侧光环内 `03 SCENARIOS`，下方五阶段指示（采集→推理→发包→判定→反馈）错峰入场。
2. **悬停导航**：INDEX / CHAINS / STACK / ACCESS / 动效 五项各自触发对应强调色（lime / violet / teal / pink / green）。
3. **按住「按住改变外观」**：600ms 后每 900ms 换一次强调色，五档循环，右上角 `#E1FF69` 同步；**松手即停**。这是落地页最强的手感演示，建议停 2 秒。
4. **声音开关**：点一下 OFF→ON（`role="switch"`，无实际音频）。
5. **链路表 + 技术栈 autoloop**：说明"表里写的是演示占位，真实过程在控制台"。
6. **邀请码**：输入 `PROBE-DEMO` 回车，出现本地反馈；输错给错误态。全程不联网。
7. **进入控制台** → 勾选「我已获得该目标的书面授权」→ 目标保持默认 `http://127.0.0.1/lab/sqli_01.php` → 剧本「三轮收敛命中」→ **开始分析**。

### 控制台主线（约 2 分钟）

8. **逐轮表**：每轮一行，看 `响应分类（WAF 拦截/正常/特征命中）`、`算子链`、`模型决策`、`耗时`。重点指出**第 2 轮的策略是被第 1 轮的响应改写的**——这就是"以响应为反馈"，不是预定义 tamper 列表。
9. **终止原因 `HIT`**：第 3 轮命中，指标卡同步（已投递 / 已拦截 / 已命中 / 平均轮次）。
10. **报告区**：结论 + 证据链表 + `mock_flag=true` 标记 → **导出 PDF（打印）**。

### 三个"反向"演示（强烈建议做，可信度全靠这个）

11. **不收敛**：剧本切「八轮未收敛」→ 跑满 8 轮，终止原因 `MAX_ROUNDS`，**不命中**。
    台词：「如果每次都成功，那说明数据是编的。收敛不了才是真实状态，我们把它也做成可展示的结果。」
12. **模型降级**：剧本切「模型降级」→ 第 2 轮起出现 `DEGRADED` 角标，降级率统计上升，日志提示"已使用兜底策略集"。
    台词：「降级必须落库、推事件、界面角标三处同步，不能悄悄降级。」
13. **越界目标**：把目标改成 `https://example.com` → 立即出现黄色声明「目标超出授权范围 · 本次为纯模拟演示 · 未向该地址发起任何请求」，报告里授权 ID 变成 `—（越界演示，无授权）`，结论写「模拟命中」。
    台词：「越界我们不偷偷跑，也不假装跑了——直接标注成纯模拟。」

## 4. 现场可调参数（改 URL 即可，不用改代码）

| 参数 | 位置 | 取值 | 说明 |
|---|---|---|---|
| `CONFIG.ENGINE_MODE` | `console.html` 脚本顶部 | `'mock'` / `'http'` | 接真引擎只切这一个字符串 + 实现 `HttpEngine.analyze()` |
| `CONFIG.TICK_SPEED` | 同上 | `'demo'` / `'fast'` / `'slow'` | 现场紧张就用 `fast`；`fast` 会自动关闭字符解码、直接定稿 |

> 注：URL 查询串**只支持 `?script=`**，没有 `?speed=`。要改速度只能改脚本顶部的 `CONFIG.TICK_SPEED`（一行）。

## 7. 答辩前必须人工确认的 6 项（环境限制，机器验不了）

1. **真实浏览器渲染**：Chrome/Edge 打开两页，确认无横向滚动条、无字体溢出、光环与切角边框位置正确。
2. **两页视觉连贯性**：主页黑底 → 控制台近黑，切换时不应有"换了个项目"的割裂感。
3. **实际 PDF 输出**：控制台跑完一次 → 导出 PDF → 打开 PDF 确认报告完整（`details` 已自动展开、水印与页码存在、无导航栏混入）。
4. **动效主观流畅度**：五档换色、autoloop、五阶段入场；若现场机器卡顿，把 `CONFIG.TICK_SPEED` 改成 `'fast'`（脚本顶部一行）。
5. **375px 窄屏**：手机或 DevTools 模拟，确认导航可换行、Hero 不裁字。
6. **离线压缩字回退**：断网状态下 `Roboto Condensed` 缺失会回退到 `Bahnschrift/DIN/Arial Narrow`，确认字宽变化可接受（已用 `font-stretch:condensed` + `letter-spacing:-.03em` 补偿）。

## 8. 合规口径（被追问时照念）

1. **不做未知漏洞挖掘**：系统只针对**已知漏洞类型（CWE 层面，不绑定具体 CVE）**做探测验证，不涉及 0day 发现，不做 fuzzing 与代码审计。
2. **只在授权范围内**：目标必须是 `localhost / 127.0.0.1 / lab 靶场别名`；越界目标一律降级为**纯模拟演示**，不发起任何请求，且界面、报告、结论三处同步标注。
3. **AI 不"挖"洞，AI 学"绕"**：创新点在"以响应为反馈、逐轮自适应决策"，不在"发现新漏洞"。对外不要用「AI 自动挖 nday」这种说法。

## 9. 评委可能问的五个问题 · 一句话答法

| 问 | 答 |
|---|---|
| 这和 sqlmap 的 tamper 有什么区别？ | tamper 是离线预定义、无状态、与响应无关的字符串变换；我们是以本轮响应为状态、由模型在线决策下一轮策略，考的是收敛而不是查表。 |
| 怎么证明"自适应"真的有用？ | 三份证据：消融实验（完整闭环 / 去反馈 / 去模型 / 静态基线 / 纯规则判定）、未预设 WAF 规则上的泛化测试、轮次—成功率收敛曲线。演示页里"八轮未收敛"就是这条曲线的一个真实采样点。 |
| 前端为什么不用框架？ | 演示件要能双击打开、断网可用、现场不装环境；单文件零依赖把不确定性降到最低。生产版按架构文档走，接口契约已经用 `MockEngine` 固定住了。 |
| 数据是真的吗？ | 全部是契约桩数据，界面每一处都打了 `mock_flag=true` 和「演示数据」标记，报告里也有。真引擎接进来只改 `CONFIG.ENGINE_MODE` 一行。 |
| 这算不算抄 soul.io？ | 借的是视觉语言与动效节奏，业务语义全部重写（DeFi 文案已清零），并且两页在 head 注释里主动声明了参考来源与刻意不采用的部分。 |

## 11. 功能页 DASHBOARD 二次设计（2026-11-08 晚）

### 改了什么

| 项 | 旧 | 新 |
|---|---|---|
| 结构 | 3×3 共 9 张同款圆角卡片（互相没有层级） | **一台仪表**：左侧主读数（跨两行）+ 右侧 1px 发丝线计量矩阵（6 格） |
| 轮次表达 | 一个裸数字 `0` | 巨型等宽数字 + `/ 上限` + **逐轮刻度轨**（一格一轮，走完填色，**降级轮直接标黄**） |
| 相对量 | 只有绝对数字 | 每格加**分段比例条**（已拦截/已投递、已命中/已投递、完成率、降级率），比例才看得出严重程度 |
| 状态 | 无 | 表头状态灯 `IDLE / RUNNING / DONE / SIMULATED / CANCELLED`，运行时酸柠呼吸、完成时转青、越界转黄、取消转红 |
| 自适应开关 | 一整张卡片 + 开关控件 | **删除**。自适应是本系统的固有属性，不是可关的选项；`ai_mode` 在报告里固定写 `ADAPTIVE`（字段保留，契约不变） |
| 轮次上限 | 独占一张卡片 | 降级为仪表脚注的一行配置常量（它是常量，不是实时计量） |

### 为什么去掉开关

原开关只做一件事：把报告里的 `ai_mode` 写成 `ADAPTIVE` 或 `STATIC_BASELINE`。留着它等于在答辩台上承认"我们的核心创新可以一键关掉"，评委只要点一下就能把项目降级成静态扫描器。真要做消融实验，那是**实验配置**，属于报告与文档，不属于演示界面。

### 视觉语言

- 沿用两页统一 token：深墨 `#0a0c0f` / 面板 `#141922` / 发丝线 `rgba(255,255,255,.07)`；主强调酸柠 `#c8f560`，次强调青 `#4fe3d0`。
- 语义色只给语义：拦截=红 `#ff6b6b`、降级=黄 `#f5c451`、投递=冷蓝 `#7ad0ff`、命中=青。**没有平均分配的彩虹配色。**
- 比例条与刻度轨共用"短刻线"语言（4px 亮 / 4px 暗的重复渐变），空态也读得出是一条量表，而不是一条下划线。

## 12. 宽屏「黑边」排查与响应式修复（2026-11-09）

### 12.1 现象与复现

大屏（≥1920）与拖动窗口改变宽度时，页面左右两侧出现比内容区更暗的竖带；窗口缩小到 1100–1300 区间时，页面还会整体左移、右侧露出一条黑带（这是横向溢出被 `overflow-x:hidden` 裁掉后的假象）。

### 12.2 根因（三处叠加，均为实测数据，不是推测）

| # | 位置 | 实测证据 | 后果 |
|---|---|---|---|
| R1 | `.wrap{max-width:1440px}` | 1920 视口下 wrap 左边界 229、宽 1440（两侧各空 229）；2560 下左边界 549；3440 下 989 | 所有视觉层（氛围辉光、顶栏/主视觉发丝线）都止步于 1440，屏幕越宽两侧「纯色暗区」越宽 |
| R2 | `.halo{width:min(34vw,420px)}` + `.stages{max-width:420px}` | 1236 视口下右列实际只有 362 宽，而光环固定 420 → `scrollWidth 1253 > clientWidth 1236`（溢出 17） | 触发横向滚动 / 页面被推移，右侧露出黑带；正好落在「拖窗口经过 1100–1300」的区间，所以表现为「缩放时触发」 |
| R3 | `body{overflow-x:hidden}` 但 `html` 未设 | 同上场景 `documentElement.scrollWidth` 仍大于视口 | `hidden` 只裁 `body`，根元素照样可横向滚动，溢出没有被真正消灭，只是看不见 |

补充：功能页 `console.html` 的 `.wrap` 上限是 1500，且顶栏 `.topbar` 带 `--bg2` 底色。1920 下取样为「内侧 (14,17,22) / 外侧 (10,12,15)」，在 x≈1530 处形成一条硬边 —— 同源缺陷的另一处表现。

### 12.3 修改点

**两个页面共同策略：容器流体化 + 溢出根治 + 视觉层全幅。**

| 文件 | 改动 |
|---|---|
| `index.html` | ①`.wrap` 由「固定 1440 + padding 40」改为「`width:100%` + `max-width:2080px` + `padding-inline:clamp(20px,3.4vw,76px)`」<br>②`html/body` 增加 `overflow-x:clip`（前置 `hidden` 作旧浏览器回退）；`min-height` 补 `100dvh`<br>③新增 `body::before` 全视口氛围层（`position:fixed; inset:0; z-index:-1`），辉光与内容宽度彻底解耦，取代原先只覆盖内容区的 `.hero::before`<br>④顶栏 / 主视觉的分隔线改用 `::after` + `left:50%; width:100vw; translateX(-50%)`，宽屏下不再中途断线<br>⑤`.hero-right` 改 `grid-template-columns:minmax(0,100%)`，`.halo` 加 `max-width:100%`，`.stages` 改 `max-width:min(420px,100%)` —— 杜绝 R2 的栅格溢出<br>⑥新增 `≥1600` / `≥2200` 两档：标题 `128→168→212px`、光环 `520→640`、副文与阶段条同步放大，避免「大屏小字 + 四周大片空」<br>⑦自定义光标 `opacity:0`，首次 `mousemove` 才 `is-live`（此前加载瞬间圆环会在视口左上角露出一段弧） |
| `console.html` | ①`.wrap` 同样流体化（`max-width:2080px`，`clamp(20px,2.8vw,64px)`）<br>②`html/body` 加 `overflow-x:clip`<br>③`.topbar` 底色改由 `::before` 以 `100vw` 铺满，边框改 `::after` 全幅发丝线（`box-shadow` 大扩散方案会连下方内容一起盖住，已弃用） |

**为什么保留 2080 上限而不是完全取消**：内容完全跟着视口走，在 3440 上单行文字会拉到 3000+ px，可读性直接崩掉。上限只作用于**内容**，背景与分隔线已经全幅，所以宽屏上不存在可见边界。
