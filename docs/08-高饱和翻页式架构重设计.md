# 高饱和翻页式架构重设计（v0.17）

> 日期：2026-11-10｜仓库：`D:\AIBBBG\Version1`（git main，基线 `a14446c`）
> 性质：**结构性大改**。用户纠偏——上一版（v0.16）做成「暗黑石墨」，与真实诉求相反；
> 本版改为**高饱和亮底撞色**，并把「单页长下滑」重构为**顶部菜单真翻页 + 小功能子页面**。
> 引擎 `console.js` 的业务逻辑（MockEngine 三剧本 / 越界诚信 / 授权闸门 / mock_flag / 8 态状态机）零改动，
> 101 项单测不回退；新增端到端 CDP 验收 35 项。

---

## 1. 设计方向（unslop 五线）

| 维度 | 内容 |
|---|---|
| Product | 隔离靶场逐轮自适应探测 WAF、每轮证据可回溯的演示控制台，面向答辩与评审观众 |
| Character | 明亮、锋利、带电（非 clean / modern / 科技感等空词） |
| World | 霓虹标牌 × 示波器 × 电路板 —— 暖白纸底上跑高饱和电流 |
| Moments | ① 监控页深色「攻防 × 神经突触」态势台（全页唯一深色高饱和焦点）；② 每页一种高饱和主色 + 实心偏移阴影的硬边数据块 |
| Signature | 硬边切角 + 方形色块状态灯 + 等宽数字读数 |

**关键取舍**：unslop 默认「chrome 安静、一处亮点」，与用户「整体高饱和」存在张力。解法是
**每页一种主色**做色彩编码（任务台青 / 监控品红 / 证据黄 / 报告蓝 / 配置紫 / 历史绿 / 说明橙），
单页内主色集中在标题方块、强调线、主按钮，其余保持纸白中性；深色只留态势台一处。
既不落入 AI 味「紫蓝渐变 + 发光」，又满足高饱和与视觉冲击。

## 2. 信息架构：从长下滑到真翻页

**7 个独立 HTML 页面**，共享 `css/core.css`（跨页过渡 / 涟漪）+ `css/console.css`（高饱和主题）+ 4 个脚本。

| 页面 | data-page | 主色 | 角色 |
|---|---|---|---|
| `console.html` | console | 青 #00BFA5 | ① 任务台：配置 / 授权 / 启动 |
| `monitor.html` | monitor | 品红 #E01E73 | ② 运行监控：态势动画随任务推进 |
| `evidence.html` | evidence | 黄 #E4C400 | ③ 证据链：逐轮表 + 结论 |
| `report.html` | report | 蓝 #2B47F0 | ④ 报告：5 附录 + PDF 导出 |
| `settings.html` | settings | 紫 #6D4DE0 | 子页面：配置快照 |
| `history.html` | history | 绿 #008F5A | 子页面：历史任务 |
| `about.html` | about | 橙 #E23B1E | 子页面：合规与说明 |

- 顶栏主导航 4 项（真 `<a href>` + `data-nav` 圆形揭幕过渡，无锚点下滑）；工具区 3 个图标入口进子页面。
- **视线引导**：任务台提交 → 自动翻到监控页执行 → 证据链回溯 → 报告收口；四步线性动线，各页一屏为主。
- section 顺序、全部静态 DOM id、`#pt` 跨页遮罩、head 首帧脚本、脚本引用顺序均保留。

## 3. 跨页状态桥（动画与任务逻辑跨页同步）

`console.js` 新增 `window.Probe.Store`（sessionStorage，`file://` 下 try/catch 降级内存）：

| Key | 内容 | 写入方 | 读取方 |
|---|---|---|---|
| `probe.cfg` | {url, vulnType, script} | 任务台（捕获阶段拦截后写） | 监控页自动恢复执行 |
| `probe.report` | 完整报告对象 | 引擎 runTask 完成后 | 证据 / 报告页恢复渲染 |
| `probe.history` | 会话内任务数组（≤30） | 引擎 runTask 完成后 | 历史页 + 各页会话指标 |

- **任务只在监控页跑一次**：任务台 `#startBtn` 的捕获阶段监听写 Store 后 `stopImmediatePropagation`，
  阻止引擎在任务台本地重复执行；再触发 `#runLink`（data-nav）翻页。
- 监控页 `app.js#bootMonitor` 读 cfg → 回填快照条 → `Probe.runTask({...,authed:true})`，
  复用同一引擎/事件/8 态状态机，动画与任务逻辑同页同步。
- 引擎新增 `runTask(opts)`（跨页共用执行核心），`start()` 保留为测试与任务台兼容入口，行为不变。

## 4. 引擎改造（零业务逻辑变更）

`webapp/js/console.js` 全部函数保留、101 项断言不回退，仅三类改动：

1. **新增** `Store` 状态桥 + `window.Probe` 导出（runTask/render*/状态机/Store）。
2. **新增** `runTask(opts)`；`start()` 改为薄封装 `return runTask()`。
3. **DOM 判空**：`setMsg/setThinking/setProgress/log/syncStart/setRunState/addRoundRow/resetUI/
   renderResult/renderReport/renderHistory` 等对每个 `$()` 结果判空，缺失元素即跳过——
   使同一引擎能在缺 DOM 的子页面安全加载而不抛错。

`resolveTerminalState` 8 态判定、`onEvent`、`applyTerminalState`、MockEngine 三剧本一字未改。

## 5. 色彩与无障碍（实测）

### 每页高饱和主色 + 按钮文字对比度

| 页 | 主色 `--key` | 按钮底 `--key-btn` | 按钮字 | 对比度 |
|---|---|---|---|---|
| 任务台 | #00BFA5 青 | #00BFA5 | 近黑墨 #0E1418 | **7.95:1** |
| 监控 | #E01E73 品红 | #C81860 | 白 | **5.59:1** |
| 证据 | #E4C400 黄 | #E4C400 | 近黑墨 #0E1418 | **10.77:1** |
| 报告 | #2B47F0 蓝 | #2339D0 | 白 | **8.18:1** |
| 配置 | #6D4DE0 紫 | #5A3BC8 | 白 | **7.26:1** |
| 历史 | #008F5A 绿 | #007A4C | 白 | **5.40:1** |
| 说明 | #E23B1E 橙 | #C5331A | 白 | **5.44:1** |

> **纠错记录**：初版用「同色系深色 ink 压同色亮底」（如 #00695C on #00BFA5）仅 2.83:1，
> 白字压亮青仅 2.33:1——均不达标。根因是中间调主色落在 WCAG 亮度"两难带"。
> 正解（unslop 原则）：**亮色底配近黑墨字；中间调底先压深再配白字**，
> 并把"高饱和强调色"与"按钮实心底"拆成两个 token（前者可亮、后者保证对比）。

## 6. 动效（随任务状态推进）

- 循环动画清零：仅 `run` 态攻防对向流（`stroke-dashoffset`）与运行 spinner 两个语义性 infinite。
- 轮次节点随 `round_no` 点亮（`.is-lit`）、降级轮斜线刻痕（`.is-degraded`）、命中关键路径一次性高亮（`.sit__path--key`）。
- 只转场 `color / background / border / opacity / transform`，统一 `160/220/320ms` + 单一缓动。
- `prefers-reduced-motion`：动画全关、氛围层隐藏，但状态灯 / 节点点亮 / 关键路径以静态形态保留（信息不丢）。
