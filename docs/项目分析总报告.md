## 0. 一句话结论

**这个项目的产品骨架做得不错，但它把唯一的创新点（"自适应闭环"）既说错了、又没在工程上做出来。**

产品侧和架构侧从两个角度指向了同一个根因：整个项目把赌注押在"AI 闭环自适应绕过 WAF"上，而现有材料里——口径上把它说成"AI 挖洞"（概念不成立），图纸上把它画成"一次性单向流水线"（闭环不可见），数据上三张表拼不出时间线（过程不可证），实验上没有任何可证伪的对照（创新不可验）。**这四件事其实是同一件事的四个面：闭环没有被定义、被表达、被留痕、被验证。**

好消息是：这些全都是**低补法**问题，不需要重写系统。改口径零成本，补契约和轮次表各一两天，做消融实验靠一个可插拔适配层就能一行切换。按下面的优先级做，性价比极高。

## 1. 项目还原：它到底做了什么

### 1.1 四层架构与数据主线

| 层 | 内容 | 负责 |
|---|---|---|
| L1 前端交互层 | 任务配置 / 大屏监控 / 漏洞结果 / 历史记录 / 报告预览 5 个页面 | 4 号开发，3 号 UI |
| L2 业务调度&存储层 | 任务调度、MySQL 三张表、PDF 报告生成；材料明确"只做调度+存储+展示" | 4 号 |
| L3 AI 自适应探测核心层 | 5 个子模块闭环，项目创新核心 | 1 号（组长） |
| L4 靶场/目标层 | DVWA 基准靶机 + 自建带 WAF（ModSecurity）站点 | 1 号 |

主线：提交 URL → 建任务 → 采参 → AI 生成/变形 Payload → 发包 → 采响应（拦截/报错/正常）→ 反馈 AI 调整下一轮 → 判定漏洞 → 入库 → 展示 / 导出 PDF。

### 1.2 L3 的五个子模块（材料声称的闭环）

1. 页面爬虫 & 参数采集 → 待测试参数列表
2. 本地大模型推理（Ollama + 提示词工程）→ 依据上轮结果判断"被 WAF 拦 / 触发漏洞"，自动变形生成新一轮 Payload
3. HTTP 发包验证 → 记录完整请求/响应、状态码、WAF 拦截特征
4. 漏洞判定（规则 + AI 语义双重判定）→ 是否存在漏洞 + 风险等级
5. 自适应反馈迭代引擎 → 把本轮结果回传模型，动态调整下一轮策略

闭环链路：**生成 Payload → 发包 → 取结果 → 反馈 AI → 生成新 Payload**。材料强调"不是一次性跑完字典，是边测边学"。

### 1.3 团队分工

1 号（技术核心，AI 核心层 + 靶场 + 脚本/提示词/测试用例/技术文档）｜2 号（路演答辩，讲稿/题库/彩排）｜3 号（视觉材料，架构图/PPT/申报书/UI 设计）｜4 号（平台开发，前端 + 调度存储 + MySQL + PDF + 一键部署）。

## 2. 第一优先：把口径改对

### 2.1 「AI 自己去挖 nday 漏洞」为什么不准确

| 概念 | 含义 | 本项目 |
|---|---|---|
| 0day | 未公开、厂商未知的漏洞；靠 fuzzing / 代码审计 / 原创 PoC **发现** | ❌ 不涉及 |
| nday | 已公开、有编号、通常已有补丁的已知漏洞；只能**复测/验证** | ⚠️ 弱相关 |
| 漏洞发现 | 产出前人不知道的新知识 | ❌ 不涉及 |
| 漏洞探测/验证 | 判断目标**是否存在**某类已知漏洞 | ✅ **这是实质** |
| WAF 绕过 | 不改漏洞本身，只改载荷外观以穿过规则匹配 | ✅ **这是创新载体** |

三个问题叠加：
- **"挖"字用错**：已知的东西谈不上"挖"，只能"验证/检出"，说"挖"会被理解成"发现新漏洞"。
- **连 nday 都算不上**：项目测的是 SQLi / XSS / 文件上传这类**漏洞类型（CWE 层面）**，未绑定任何具体 CVE/CNVD 实例，严格说是"已知漏洞类型的自动化探测"。
- **与材料自相矛盾**：材料里已写死边界「不主打 0day、主打 WAF 环境下自适应绕过探测已知漏洞」，口头却说"AI 自主挖洞"——团队自己给了两套定位。

### 2.2 不改会怎样

评委一旦问「挖出了哪个 CVE / 有没有原创 PoC」，答不上即被判"夸大、不严谨"，全盘可信度受损；且会被按"漏洞挖掘"的高标准衡量一个扫描器范畴的作品，落差巨大；"AI 自主挖洞 / 攻击"还主动送上"套壳蹭概念"与合规质疑的把柄。**最可惜的是：项目最值钱的"闭环自适应 + 过程可解释"被这句话埋没了。**

### 2.3 建议统一口径（申报书 / PPT 首页 / 讲稿一字不改）

> 本系统是面向**授权目标**的 Web 漏洞检测辅助工具：在存在 WAF 防护的场景下，通过**本地大模型对每轮探测响应做闭环反馈、自适应变形探测载荷**，提升对**已知漏洞类型**（SQL 注入、XSS、文件上传等）的检出能力并降低误判，用于企业自测与等保自查；**不涉及 0day 或未知漏洞挖掘，不用于未授权目标**。

答辩口语版：**「AI 不'挖'洞，AI 学'绕'——我们解决的是：有 WAF 挡着的时候，已知漏洞怎么还能被测出来、怎么把过程讲清楚。」**

用词替换：AI 挖漏洞/挖 nday/自主挖洞 → AI 自适应探测；AI 发现漏洞 → AI 检出漏洞；攻击/拿下站点 → 探测/授权验证；**超越/替代 sqlmap → 对现有扫描器在 WAF 场景下的补充与增强**；0day/未知漏洞 → 已知漏洞类型。

## 3. 创新成色：取决于三份证据

### 3.1 三类创新分开讲

| 类别 | 内容 | 怎么讲 |
|---|---|---|
| **真创新**（需证据） | ① 以 HTTP 响应为反馈状态的闭环自适应生成；②「WAF 拦截 vs 真正触发」的语义判别；③ 离线、数据不出域的本地推理闭环 | 新颖性来自**把 LLM 用作闭环控制器里的策略函数**，而非 LLM 本身 |
| **工程整合创新** | 5 子模块端到端、大屏过程可视化、规则+语义双重判定、全量留痕 + 标准化 PDF、一键部署 | 讲成「完整、可用、可复现的系统」，**不要讲成"我们发明了这些技术"** |
| **伪创新 / 易被质疑** | "AI 挖洞"（删）、"大模型生成 Payload"（若本质是提示词列技巧让模型挑）、"边测边学"（若成功率不随轮数提升）、"降低误报"（无量化）、"本地部署"（是选型不是创新） | 主动降调或补证据，否则变扣分项 |

### 3.2 三份证据（分水岭）

1. **消融实验**：A 完整闭环 / B 去掉反馈 / C 去掉模型 / D 静态变换基线 / E 纯规则判定，看曲线能否分离。
2. **泛化测试**：在一套**未参与提示词与算子设计**的 WAF 规则上重跑，证明不是背答案。
3. **轮次—成功率收敛曲线**：证明迭代确实有效，而非"随机重试"包装成"学习"。若 A 组与 B 组曲线几乎重合，**如实把"自适应"降调为"自适应重试"**。

诚实退路必须在架构上预留，不要把自己逼到只能嘴硬。

### 3.3 与 sqlmap 的正确关系

**差在"状态"和"决策者"，不在"变换技巧"本身。**

| 对比项 | sqlmap tamper + 启发式 | 本项目 AI 闭环（若真正做到） |
|---|---|---|
| 变换从哪来 | 人事先写好的有限变换函数集合 | 模型在线生成/组合 |
| 是否感知本次响应 | **否**，无状态、按预设顺序串联 | **是**，本轮拦截特征/状态码是下轮输入 |
| 谁决定下一个怎么变 | 人或固定策略 | 模型依据本轮反馈做策略决策 |
| 遇到没见过的 WAF 规则 | 需人工新增 tamper | 理论上可泛化（需实验证明） |

注意澄清：sqlmap 的**启发式/布尔盲注判定**解决的是"这里有没有注入"（判定问题），不解决"WAF 把我拦了我该怎么改载荷"（生成问题），不能拿来当"sqlmap 也有闭环"的反驳。

**定调建议**：把 sqlmap 设为**基线对照组**，结论收窄为"在 WAF 拦截这一特定条件下，闭环自适应相比静态 tamper 能显著降低假阴性"，而不是"我们比 sqlmap 强"。范围越窄，越无可辩驳。

竞品全景（AWVS / Burp / ZAP / AI 辅助渗透类）与逐维对比表见 `01-产品与评审分析.md` 第 4 节。

## 4. 架构评审：骨架合格，控制面缺失

### 4.1 定档

`分层 A- ／ 控制面 C- ／ 证据链与接口契约 D（P0 必修）`

**一句话**：原架构是一张**功能框图而非控制架构图**——正确回答了"有哪些模块、数据往哪流"，但没回答"一轮怎么结束、下一轮凭什么开始、什么时候停、怎么证明这一过程真实发生过"。图3 上只有跨层单向反向箭头，**没有 AI 层内部的层内自环**，读起来是"提交一次 → 发一次包 → 收一次响应 → 出一次结果"的单向流水线。**图纸自己否认了自己的卖点**，比讲稿讲错更致命。

三处名实不符：
- L3 把**控制逻辑**（决定下一轮、决定何时停）与**执行逻辑**（发一个包、判一个响应）混在同一层且无主从 → 建议在 L3 内切「控制面 / 执行面」两个子平面，不打乱四层骨架。
- "调度层不做判定"与架构图回流箭头标注"识别漏洞"存在歧义 → 改为「本轮判定结果（结构化）」，写死"判定唯一执行主体是 L3，L2 只透传与持久化，不得改写 verdict"。
- "成果输出：安全测评报告"是**交付物**不是运行时层，应降格为从 L2 引出的输出支路，且报告生成收敛到唯一入口。

### 4.2 八个结构性缺口（7 个是 P0）

| # | 缺口 | 不补的后果 | 最小补法 |
|---|---|---|---|
| ① | 任务/轮次状态机与收敛终止 | 循环失控、无法定义收敛、现场卡死 | `max_rounds`(8–12)、`budget_ms`、枚举状态机、`terminate_reason`、三条终止判据 |
| ② | **逐轮迭代日志与证据链** | **答辩命门**：无法回答"怎么证明不是硬编码" | 新增 `round` 表为主轴，强制 `prev_round_id`，原 payload 表降为 `payload_attempt` |
| ③ | 模型输出结构化约束与校验 | 格式漂移打断链路、越界输出造成工程与合规事故 | 固定 JSON Schema + 算子白名单 + 点位校验三重门 + 2 次重试即兜底，**未校验不得进发包器** |
| ④ | L3↔L2 接口契约冻结 | 1 号改一次输出结构，4 号前后端全返工 | T01 冻结 `api-contract.md`，统一响应格式，幂等键 `(task_id, round_no)`，只增字段不改语义 |
| ⑤ | 实时进度推送 | 大屏看不到逐轮过程 | **选 SSE**（单向事件流、原生重连、现场穿透好），WebSocket 过重、轮询仅作降级 |
| ⑥ | 并发/限流/超时/熔断/靶场保护 | 多任务多轮把自己靶场打垮，演示失去被测对象 | 默认单活跃任务、单请求超时、靶场侧限流、模型熔断 |
| ⑦ | 授权校验与审计 | 合规质疑一问就穿（完整请求响应含 Cookie/Token 入库并导出） | 创建任务强制授权勾选、服务端 scope 硬校验、入库脱敏、报告水印、`audit_log` |
| ⑧ | 模型服务抽象层 | **三份证据做不出来**：每组消融都要改闭环代码，最后必然放弃 | `ModelAdapter` 四实现（Ollama / 无反馈 / 无模型 / 静态基线），`group_tag` 一行切换零代码改动 |

> 关键洞察：⑧ 是**用架构缺口卡死实验能力**的典型——它直接决定第 3.2 节三份证据能不能做。补它比多写两个页面重要得多。

### 4.3 闭环状态机与"防随机重试"

一轮流转：采参 → 生成 → 校验 → 发包 → 响应分类 → 判定 → 留痕 → 反馈 → 收敛判据 →（未收敛且预算有余）回到生成 ★。

`FeedbackState` 是**整个项目最关键的数据结构**，定长、不随轮次增长，至少包含：上轮 ID（因果链）、`waf_signal`（拦截特征）、`response_fingerprint`、`response_class`（BLOCKED/ANOMALY/NORMAL/TIMEOUT）、`hit_signal`、`verdict/confidence`、`history_summary`（最近 K 轮压缩摘要）、`tried_strategies`、`failed_strategies`、`budget_remaining`、`model_decision_raw`、`adapter_name/group_tag`、`degraded_flag`。

防退化为随机重试靠四件事：**策略指纹去重 + 失败策略记忆 + 响应驱动（上/下轮指纹相同则记为无效增益）+ 收敛判据（连续 K 轮无增益即终止）**。评委可以直接看 `tried_strategies` / `failed_strategies` 随轮次增长，而不必相信口述。

### 4.4 本地大模型的现实边界

**定性推断（不编数字，具体数值须现场实测）**：小模型指令遵循与结构化输出稳定性波动明显；全量历史入模会触顶上下文并显著变慢；本地 CPU/弱 GPU 单轮延迟可能达到评委能感知的量级；冷启动更慢；并发能力有限。

由此产生 5 条取舍：
1. **把"生成"收窄为"策略选择/组合"**——不让模型自由写载荷文本，只在预置算子白名单内选编号序列并给理由。生成空间有限，稳定性/合规性/可校验性同时解决。
2. 多轮对话改造成**定长状态对象**（上下文问题从模型侧移到工程侧）。
3. 模型放在**建议者**位置，输出经 Validator 放行才成为动作。
4. 低温度 + 固定种子 + `prompt_version/schema_version` 落库，换取可复现。
5. 把"离线"讲成**取舍**（牺牲模型能力换数据不出域 + 断网可用），不是纯优势。

**职责红线**：模型管「下一轮怎么变」，工程管「能不能变、发不发、算不算、停不停」。模型不承担最终漏洞判定、发包控制、无校验自由生成、预算与终止决策、授权范围判断、敏感数据处理。这条线画清楚，"套壳"质疑就有正面答案。

**降级三铁律**：降级必须可见（落库 + SSE + 大屏角标三处同步，偷偷降级等于学术不端）；降级轮次从主指标单列；模型完全不可用时切预录日志回放，但必须**当场声明非实时**。

## 5. 双重判定、靶场与演示可行性

- **判定框架**：推荐「规则门控 + 语义分量融合」——只有"规则判不准"的存疑样本才调模型，既省推理、又让"降误报"的作用域清晰可量化。输出显式三态（存在 / 未发现 / 需复核），双阈值标定并写入配置快照。**`response_class=BLOCKED` 不进漏洞判定统计**，这是消除"把被拦当成没洞"这一假阴性来源的关键。
- **误报量化**：三类标注集（BLOCKED / ANOMALY / NORMAL），仅限本地隔离靶场、双人独立标注 + 分歧仲裁、**不得用模型自己生成的样本当真值**；出混淆矩阵，与"纯规则基线"对比时**共享同一份响应样本做离线重判**，避免绕过成功率污染判定对比。样本不足就如实写"小样本验证，列为后续工作"。
- **靶场结论分档**：ModSecurity + DVWA **足以支撑**「给定规则集内降低假阴性」与「离线闭环跑通、过程可解释」；**不足以支撑**「泛化性」与「超越 sqlmap」。须另备 ≥1 套未参与设计的规则做泛化组。
- **一个易忽略的隐患**：WAF 规则太简单会**一轮就过**，大屏看不到多轮自适应，反而坐实"预先写好"的怀疑。建议把规则强度调到**需 2–4 轮收敛、且每轮拦截特征类型不同**的区间，规则集版本作为配置快照留存。
- **对比公平性「四同」**：同注入点、同漏洞类型、同 WAF 规则集版本、同轮次预算（外加同起点、同一时间窗）。任一不一致，对比结论即不成立。主动讲控制变量比被追问更显严谨。
- **现场兜底**：断网 → 全链路本地，抓包自证零外部 API，把断网变成卖点；无 GPU/加载慢 → 开场前预热 + "模型思考中"进度态 + 健康检查预告警；模型崩 → 熔断降级并显式标注；靶场挂 → 单活跃任务 + 限流 + 快速重启脚本。

## 6. 风险优先级（合并两份产出后的 Top 清单）

| 级别 | 风险 | 所有权 |
|---|---|---|
| **最高** | 口径错（AI 挖洞 / 0day / 超越 sqlmap）→ 可信度全盘受损 | 全队，2 号讲稿 + 3 号材料核对 |
| **最高** | 闭环在设计上不成立：无状态机、无层内自环、无收敛定义 | 1 号（控制面） |
| **最高** | 逐轮证据链缺失 → "怎么证明不是硬编码"无解 | 4 号建表 + 1 号产出字段 |
| **最高** | 三份证据做不出来 → 创新降级为"套壳/工程整合" | 1 号（ModelAdapter + 实验） |
| **最高** | 接口未冻结 → 最后一周前后端返工 | 1 号 + 4 号共同（T01） |
| **高** | 技术单点全压 1 号，实验最容易被挤掉 | 全队排期：靶场/测试用例/契约文档分出去；2 号从首周介入实验记录 |
| **高** | 模型输出不可控、闭环不收敛、拦截特征难区分 | 1 号（Validator / 去重 / 标注集） |
| **高** | 合规边界失守（未授权目标、原始凭据入库、报告含敏感内容） | 4 号 + 全队口径 |
| **高** | 降级未标注的诚信风险 | 全队 |
| 中 | 留痕数据膨胀、靶场被打垮、证据链时间线不可信、报告出口重复 | 4 号 |

**风险分布判断**：高等级风险绝大多数落在「控制面 + 证据链 + 契约」，与八个缺口高度重叠。**本项目当前的技术风险不是"AI 会不会生成载荷"，而是"闭环有没有被工程化地定义、留痕和证伪"。**

## 7. 行动清单（按性价比排序）

**立刻做（零成本 / 低风险）**
1. **改口径**：按 2.3 统一申报书、PPT、展板、讲稿、页面页脚，删掉"挖洞/0day/超越 sqlmap"，单设「合规与边界」页。由 3 号逐条核对用词替换表，2 号讲稿开头主动先讲边界。
2. **改架构图**：在 L3 内部补**层内自环**，把发包箭头标注「按轮次重复（上限 N）」，反向链路在 L3 处分叉（一条回控制面、一条去 L2），「成果输出」降格为输出支路。图纸必须自己就能讲清"自适应"。

**第一周（决定后面会不会返工）**

3. **T01 冻结 `api-contract.md`**：十接口字段、状态/事件/终止原因/verdict 枚举、表结构、脱敏规则一次性定死，1 号 4 号共同确认，此后只增字段不改语义。**这是 4 号不被返工的唯一保障，必须在 1 号动手写闭环之前完成。**
4. **补 `round` 轮次表 + 逐轮日志接口**：任取一轮能回答"第几轮 / 依据上轮哪条响应 / 模型原文说了什么 / 校验是否放行 / 本轮结论与耗时"，支持导出 JSON 证据链。
5. **做 `ModelAdapter` 四实现**：`group_tag` 一行切换消融组，把三份证据的成本压到最低。

**中期里程碑（全队对齐点）**

6. **端到端跑通 1 类漏洞 + 1 套 WAF 规则 + 完整日志 + 对比演示录屏**。在此之前 2 号开始写答辩题库、3 号定视觉规范与用词表，把后期压力前移。
7. **跑三组实验出收敛曲线**，如实标注样本量与降级轮次，不编数字、不美化坐标轴。

**收缩底线**：时间极紧时保「1 类漏洞 + 1 套规则 + 完整日志 + 对比演示 + 消融曲线」；**砍"迭代日志"或砍"消融实验"，创新与可信度会同时失守**。反过来，多支持两类漏洞、报告模板精修、UI 动效这些都可以砍。

完整的 17 项任务分解（含依赖图、验收标准、角色分配）见 `02-架构与技术评审.md` 第 9 节。

## 8. 合规与伦理边界（务实版）

- **授权**：只用于自己拥有或已获书面授权的目标。建议在任务配置页加**必填授权确认勾选项**，服务端二次校验目标在 `scope` 白名单内，授权 ID / 授权人 / 时间写入 `task` 表留痕——让"授权"成为可追溯的**产品字段**而非口头声明。
- **靶场**：演示一律在 DVWA / 自建带 WAF 靶场，材料明确标注"演示环境为本地隔离靶场"，不出现任何真实域名、IP 或真实站点截图。
- **数据**：系统留存完整请求/响应，可能含 Cookie、Token、业务数据 → 入库与导出前脱敏（凭据类字段替换 + 超长截断 + `desensitized` 标记），限定留存期与清理入口。
- **报告**：含"成功绕过载荷"与请求响应证据，属敏感内容 → 首页固定"仅限授权范围内使用"、任务 ID 水印、控制分发。
- **答辩**：讲稿开头主动先讲边界，把伦理质疑提前化解，比被追问更显成熟。

## 9. 需要你补充的信息（决定后续判断精度）

| # | 问题 | 为什么关键 |
|---|---|---|
| 1 | **"自适应"目前实现到什么程度**：模型真读本轮响应后生成新载荷，还是提示词里列若干变形技巧让模型挑/组合？有没有显式反馈状态对象？ | 决定创新成色、答法能否站住、控制面是"补"还是"从零建" |
| 2 | **有没有实测与消融数据**：绕过成功率、收敛轮数、误报对比、与 sqlmap/tamper 基线对比；是否已在未预设 WAF 规则上跑通 | "真创新 vs 套壳"的分水岭 |
| 3 | **竞赛类别与评分口径**：网安作品赛 / 创新创业 / 毕设？权重偏原创性还是工程完整度 | 决定答辩把"闭环创新"还是"系统完整度"放前面，也决定 P0 取舍 |
| 4 | **现场硬件与模型规格**：CPU/内存、有无 GPU、拟用 Ollama 模型、冷启动与单轮推理**实测**耗时 | 决定降级预案、大屏进度态、讲稿能否给实测区间 |

| 6 | **时间表与当前完成度**：距答辩多久、5 个子模块各自进度、对比演示是否已录屏 | 决定 P0 是否进一步收缩、中期里程碑设在哪一周 |

其中 **#1、#2、#5** 建议优先确认：分别决定控制面工作量、创新证据能否成立、泛化测试能否做。

## 10. 主理人综合判断

两份产出高度互补，且**没有分歧，只是同一根因的两个切面**：

- 产品侧说「**说错话**」：定位口径把强项藏起来、把弱项顶到评委枪口上。
- 架构侧说「**控制面缺失**」：图纸和数据模型里根本没有"逐轮"这个概念。
- 合起来看：**团队把创新点押在"自适应"上，却既没有把它说准，也没有把它做成可验证的系统。**

对竞赛作品的一个现实判断：这套设计的**产品完整度**（四层架构、五个页面、大屏、PDF 报告、四人分工）其实已经不错，评委吃过见过；真正拉开差距的不是"多做两个页面、多支持一类漏洞"，而是**可验证性**——能不能当场 live 跑、能不能请评委随机指定参数、能不能打开逐轮日志证明载荷是当轮生成的、能不能拿出三组分离的曲线。

因此最值得做的资源调配是：**把人力从"功能数量"转移到"证据链 + 三组曲线 + 口径统一"**。这三件事都不需要新技术，只需要把已有的闭环工程化、诚实化。做完之后，即便结论收窄成"在给定 WAF 规则集内降低假阴性"，这个作品也远比现在稳。
