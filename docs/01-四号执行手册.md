## 第一章 契约桩解耦：不要等 1 号，自己造一个假 1 号

> 这一章是整本手册的地基。如果只做一件事，做这个。

### 1.1 问题定义（把处境说准）

你的 6 项 P0（T02 授权 / T04 证据链 / T08 调度 / T09 SSE+大屏 / T12 报告 / T16 部署）里，**5 项的输入来自 1 号的引擎，但 5 项的输出全部是你自己的**。这意味着：

- 你真正被卡的，**只有"轮次事件长什么样"这一个信息**；
- 而这个信息**不需要等 1 号的代码，只需要等他的字段签名**；
- 字段签名 = T01 契约。所以：**T01 一冻结，你就完全自由了**。

但现实是 T01 也可能拖。所以再加一层保险：**T01 没冻结之前，你自己写一版契约草案 v0.1，然后按自己的草案先写 MockEngine**。理由很实际——把"空白的接口"变成"一份写满字段的提案"，1 号的认知成本从"从零设计"降到"改 or 确认"，他同意的概率高一个数量级。**这是你作为最大受益者必须主动做的事，不能等。**

### 1.2 什么是契约桩（Contract Stub）

一句话：**一个假装自己是 1 号引擎的进程，严格按 `api-contract.md` 返回"假但合法"的轮次数据。**

它要满足三个条件，缺一不可：

| 条件 | 具体要求 | 为什么 |
|---|---|---|
| **接口同构** | 与真引擎暴露**完全相同的路径、字段名、枚举值、响应包壳** | 切换时只改 `baseURL`，业务代码零改动 |
| **行为可信** | 有轮次节奏、有多轮收敛、有拦截标记、有降级分支 | 前端才能开发出"真实感"的 UI，而不是贴假数据 |
| **身份可辨** | 每条记录带 `mock_flag=true`、`adapter_name="MOCK"`，落库、SSE、导出 JSON 全链路可见 | 防止假数据污染实验统计与答辩陈述 |

**"身份可辨"是诚信红线**。MockEngine 造的是开发脚手架，不是演示素材。任何情况下 mock 数据不得进入消融实验、不得在答辩中伪装成 live。如果答辩要用它兜底，必须当场说"当前为契约桩回放，非实时推理"——这句话说出来是加分（工程严谨），瞒过去被拆穿是灾难。

### 1.3 MockEngine 必须实现的三件事

**① 接口面（3 个端点，一个不能少）**

| 端点 | 作用 | 备注 |
|---|---|---|
| `POST /api/v1/engine/rounds:execute` | 契约接口 4，下发单轮、拿回本轮结果 | 至少实现 `exec_mode=sync`，`async` 可先返回 202 + 立即回调 |
| `POST /api/v1/internal/rounds/{round_id}/result` | 契约接口 5，异步回调（Mock 主动打你） | 用来验证你的回调落库与幂等 |
| `GET /api/v1/health/model` | 契约接口 8，模型健康 | 用来开发大屏"模型状态"角标与熔断预警 |

**② 三套剧本（不是一套，否则你测不出异常分支）**

| 剧本 | 轮次走向 | 验证你什么能力 |
|---|---|---|
| `MOCK_CONVERGE_3` **（默认）** | 第 1 轮 `BLOCKED`（特征类型 A）→ 第 2 轮 `BLOCKED`（特征类型 B，算子已变形）→ 第 3 轮 `ANOMALY` + `hit_signal=true` → `terminate_reason=HIT` | 大屏多轮展示、证据链因果链、收敛曲线有平台段、报告有结论可溯源 |
| `MOCK_NO_CONVERGE` | 8 轮全 `BLOCKED`，每轮特征轮换 → `terminate_reason=MAX_ROUNDS` | 轮次计数、预算耗尽、报告出"未发现"结论、**大屏不得卡死在最后一轮** |
| `MOCK_DEGRADED` | 第 1 轮正常 → 第 2 轮起 `fallback_used=true` + `degraded_flag=true`，走兜底策略标签 → 第 4 轮 `BLOCKED` 收尾 | 降级角标、`degraded` 事件、报告里降级轮次单列、熔断语义 |

三套剧本由环境变量选：`MOCK_SCRIPT=MOCK_CONVERGE_3|MOCK_NO_CONVERGE|MOCK_DEGRADED`。

**③ 节奏控制（这一条最容易被做错）**

轮次间与事件间要有**可配置的延迟**，否则前端开发的 UI 会在 100ms 内全部冲完，你根本看不到"进行中"该长什么样。

| 模式 | 事件间隔 | 单轮总时长 | 用途 |
|---|---|---|---|
| `MOCK_TICK=fast` | 0.2s | ≈0.6s | 前端联调、自动化自检 |
| `MOCK_TICK=demo` | 1.2s ~ 3.0s（随机抖动） | ≈4s ~ 8s | 大屏视觉调试、彩排 |
| `MOCK_TICK=slow` | 6s | ≈18s | **专门用来测"看起来像死机"** —— 验证心跳、呼吸灯、"模型思考中"是否救得回来 |

**必须用 `slow` 跑一遍大屏**，这是唯一能提前发现"静止画面"问题的方法。

### 1.4 每轮必须产出的 7 类事件（一条都不能少）

严格按架构冻结的事件枚举，每条都必须带 `task_id / round_no / timestamp / degraded_flag` 四个公共字段：

| 事件 | 何时发 | 大屏上体现为 |
|---|---|---|
| `round.started` | 本轮开始 | 轮次计数器 +1，时间线新增一行 |
| `payload.generated` | 策略产出后 | "当前变形策略"卡片刷新（`strategy_tag` + `rationale`） |
| `request.sent` | 发包瞬间 | "发包中"状态点闪烁 |
| `waf.blocked` | 分类为 `BLOCKED` | **红色拦截标记**（这是评委最爱看的一格） |
| `verdict.ready` | 判定完成 | 绿色/灰色判定标签 + `confidence` |
| `degraded` | 本轮走兜底 | 顶部/卡片 **DEGRADED 角标** |
| `task.terminated` | 终止 | 大屏进入"已终止 + terminate_reason"态 |

另加两个自定义事件（EventSource 允许任意 event 名，不算改契约）：
- `task.started`：任务进入 `ITERATING`；
- `heartbeat`：服务端每 15s 主动推一条，兼任 SSE 心跳与"系统还活着"的视觉证据。

**关键设计**：事件里**只带轻字段**（`round_no / event / timestamp / response_class / strategy_tag / degraded_flag / mock_flag`），**不塞 `model_decision_raw`、不塞响应片段**。前端收到事件后调 `GET /rounds?from_round=N` 拉详情。理由：事件流是广播通道，塞大会拖慢并放大重连成本；详情走拉取还能天然做分页与缓存。

### 1.5 核心实现骨架（20 行内）

```python
# mock_engine.py —— 剧本驱动，全局只依赖契约字段名
SCRIPT = {  # 每轮：分类 / 拦截特征类型 / 策略标签 / 是否命中 / 是否降级
    1: dict(cls="BLOCKED", sig="RULE_KEYWORD_A", tag="OP_BASE",       hit=False, fb=False),
    2: dict(cls="BLOCKED", sig="RULE_KEYWORD_B", tag="OP_ENC_SEQ_1",  hit=False, fb=False),
    3: dict(cls="ANOMALY", sig=None,             tag="OP_ENC_SEQ_2",  hit=True,  fb=False),
}

async def run_mock(task_id: str, n_max: int = 8, degrade_from: int | None = None):
    for no in range(1, n_max + 1):
        s = SCRIPT.get(no, dict(cls="NORMAL", sig=None, tag="OP_FALLBACK", hit=False, fb=False))
        fb = bool(degrade_from and no >= degrade_from)
        tick = mock_tick_delay()                      # fast / demo / slow 三档
        await emit(task_id, "round.started", no, degraded_flag=fb)
        await emit(task_id, "payload.generated", no, strategy_tag=s["tag"], degraded_flag=fb)
        await asyncio.sleep(tick)
        await emit(task_id, "request.sent", no, degraded_flag=fb)
        await asyncio.sleep(tick)
        await emit(task_id, "waf.blocked" if s["cls"] == "BLOCKED" else "verdict.ready",
                   no, response_class=s["cls"], waf_signal=s["sig"], hit_signal=s["hit"],
                   degraded_flag=fb, adapter_name="MOCK", mock_flag=True)
        if s["hit"]:
            return await emit(task_id, "task.terminated", no, terminate_reason="HIT", mock_flag=True)
    await emit(task_id, "task.terminated", n_max, terminate_reason="MAX_ROUNDS", mock_flag=True)
```

配套要求：

- `emit()` 内部**必须先写库、再推 SSE**（顺序反了会出现"大屏有事件、点进去查不到该轮"的诡异 bug）；
- 每次 `emit` 生成单调递增 `seq`（`round_no * 100 + 事件序号`），写进 SSE 的 `id:` 字段，供 `Last-Event-ID` 续传；
- `response_fingerprint` 用 `sha256(round_no + cls)` 造一个稳定假值，别留空——前端要拿它判断"上轮与本轮是否同一个拦截页"；
- `prev_round_id` 必须真的指向上一条 `round_id`，这是证据链唯一的因果字段，**Mock 也要演对**，否则你的"依据上轮哪条响应"那一栏在联调时才发现是空的。

### 1.6 MockEngine 的目录与切换方式（假设无框架约束）

```
project/
├─ app/                     # 4 号后端（FastAPI）
│  ├─ api/                  # 路由 + 统一响应包壳 + 授权中间件
│  ├─ services/             # TaskService / ReportService / ProgressHub
│  ├─ storage/              # 表定义、脱敏、审计、留存清理
│  └─ engine_client/        # ★ 引擎客户端（唯一与 1 号耦合的地方）
│     ├─ base.py            # EngineClient 抽象：execute_round / health / on_result
│     ├─ http_client.py     # 真实实现：打 1 号的 HTTP 契约
│     └─ mock_client.py     # ★ 契约桩实现：进程内模拟，剧本驱动
├─ mock_engine/             # 可选：独立进程，模拟"1 号的引擎"
│  └─ main.py               # 暴露 engine 三个端点，便于独立起停
└─ web/                     # 4 号前端（Vite + React + TS）
```

**切换只需一个配置**：

```bash
# .env
ENGINE_MODE=mock            # mock | http
ENGINE_BASE_URL=http://127.0.0.1:8100
MOCK_SCRIPT=MOCK_CONVERGE_3
MOCK_TICK=demo
CONTRACT_VERSION=1.0
```

切换动作本身是 **L0 级变更**（改环境变量 + 重启），不碰业务代码。如果切换需要改代码，说明你的抽象漏了——**这是 4 号自己的一道自检**。

### 1.7 契约桩的验收标准（逐条打勾才算完）

- [ ] 三套剧本都能跑完，`terminate_reason` 分别为 `HIT / MAX_ROUNDS / MAX_ROUNDS`；
- [ ] 三档 `MOCK_TICK` 都试过，`slow` 模式下大屏**不出现超过 8 秒的静止画面**；
- [ ] 每个事件都能在 DB 里查到对应 `round` 记录，且 `round.prev_round_id` 环环相扣（第 1 轮为 `NULL`）；
- [ ] 断网重连后 `?Last-Event-ID=N` 能续上，**不重不漏**（用 `slow` 模式最容易验证）；
- [ ] `mock_flag=true` 在 DB、SSE、`GET /rounds`、导出 JSON、PDF 五处全部可见；
- [ ] 把 `ENGINE_MODE` 从 `mock` 改 `http` 指向一个空端口，系统**优雅报错**（`50301 模型不可用`）而不是白屏或 500 堆栈；
- [ ] 同一 `(task_id, round_no)` 重复下发两次，`round` 表只有一条，第二次返回既有记录。

**完成这一章，你的 6 项 P0 里有 5 项从此不再依赖 1 号。** 剩下的唯一依赖是 T10 联调时的那一次"真引擎替换"，那是几十分钟的配置工作，不是几周的重写。

## 第二章 先做什么后做什么

### 2.1 总原则：三条并行轨道

```
轨道 P（平台，你独立）：  DB → 授权/审计 → SSE+大屏 → 报告 → 部署包      ← 不等任何人
轨道 E（契约，你推动）：  契约草案 v0.1 → 冻结 v1.0 → MockEngine → 联调   ← 需要 1 号拍板
轨道 J（联调，被阻塞）：  真引擎接入 → 端到端跑通 → 三份证据数据采集      ← 必须等 1 号
```

**你 80% 的时间应该在轨道 P。** 轨道 E 只需几小时的会议 + 半天的文档。轨道 J 才需要"等"，而它排在第二周末才启动——**只要你把 P 做在前面，"等"就不会阻塞你**。

| # | 任务 | 依赖 | 产出物 | 验收标准 | 并行性 |

## 第三章 和 1 号谈契约的具体清单

> 本章是 4 号**唯一需要"跨人协作"**的地方，也是最容易谈崩的地方。原则：你出草案、他做减法、当场定枚举、事后只增不改。

### 3.1 开会前先明确：你需要的不是"接口文档"，是 4 个枚举 + 1 个对象

很多人谈契约谈成了"接口清单"，结果字段名对了、**语义不对**，联调照样返工。真正的雷区只有 5 个：

1. **4 个枚举的值域**（状态 / 事件 / 终止原因 / verdict）——值域一定，前端就能写死渲染逻辑；
2. **`FeedbackState` 哪个子集要落库给前端看**——这个定了，你的表就定了；
3. **判定结果结构**（`verdict` + `confidence` + `evidence_round_ids` + `verdict_source`）——这个定了，报告就能写；
4. **幂等语义**（`(task_id, round_no)` 重复下发返回什么）——这个定了，调度器就不会重复发包；
5. **错误码**（尤其"模型不可用"和"超时"要分开）——这个定了，大屏就能区分"卡住"和"降级"。

**开会时按这 5 项逐条过，逐条念出取值域，让 1 号当场说"行"或"改一个"。** 不要在会上讨论实现，只讨论名字。

#### D. `FeedbackState` 里"必须落库给前端看"的子集

这个字段表是整个项目最关键的，但**不是全部都要给前端**。你只需要这 8 个落库、这 4 个上大屏：

| 子字段 | 落库 | 上大屏 | 上报告 | 用途 |
|---|---|---|---|---|
| `prev_round_id` | ✅ | ✅ | ✅ | **因果链唯一证据**："依据上轮哪条响应" |
| `waf_signal` | ✅ | ✅ | ✅ | 拦截类型 → 大屏红标 + 报告拦截归因 |
| `response_class` | ✅ | ✅ | ✅ | 四色标签 |
| `response_fingerprint` | ✅ | ❌ | ✅ | 判断"本轮与上轮是否同一个拦截页"（无效增益） |
| `history_summary` | ✅（截断 2000） | ❌ | ✅ | 证明上下文被压缩、不是全量灌模型 |
| `tried_strategies` | ✅（JSON） | ❌ | ✅ | **证明策略去重生效**，评委可直接看它随轮增长 |
| `failed_strategies` | ✅（JSON） | ❌ | ✅ | **证明失败记忆生效**，比口述有力 |
| `budget_remaining` | ✅ | ✅ | ❌ | 大屏"剩余预算"提示，解释为什么终止 |
| `model_decision_raw` | ✅ | ❌（只在详情抽屉） | ✅ | **答辩命门**：模型原文 |
| `verdict` / `confidence` | ✅ | ✅ | ✅ | 结论 |
| `adapter_name` / `group_tag` | ✅ | ✅（角标） | ✅ | 消融归因 |
| `hit_signal` | ✅ | ✅ | ✅ | 命中高亮 |
| `degraded_flag` | ✅ | ✅（醒目角标） | ✅ | 诚信标记 |
| `task_id` / `round_no` | ✅ | ✅ | ✅ | 坐标 |

> **要跟 1 号明确一句**：`tried_strategies` 和 `failed_strategies` **必须是可直接渲染的字符串数组 / 键值对**，不能是"模型自然语言里提到的策略"。如果它俩最后是自由文本，你在报告里就没法做"重复策略比例"统计，架构要的证据就断了。

#### E. 四个必须当场定死的枚举

```text
TaskStatus:   CREATED | PARAM_COLLECTING | ITERATING | TERMINATED | REPORTED
              | CANCELLED | FAILED | DEGRADED

RoundStatus:  PENDING | GENERATED | VALIDATED | SENT | CLASSIFIED | JUDGED
              | PERSISTED | FAILED | SKIPPED

ResponseClass: BLOCKED | ANOMALY | NORMAL | TIMEOUT

Verdict:      VULNERABLE | NOT_FOUND | NEEDS_REVIEW

TerminateReason:
  HIT                     命中，正常终止
  CONVERGED               连续 K 轮无增益
  MAX_ROUNDS              轮次耗尽（记为未收敛，不得算成功）
  BUDGET_EXHAUSTED        budget_ms 耗尽
  TIMEOUT                 单轮或任务级超时
  CANCELLED               人工取消
  MODEL_FALLBACK_EXHAUSTED 降级链路也走不通
  NO_PARAM                无可用探测点位
  ENGINE_ERROR            引擎异常

Event:
  task.started | round.started | payload.generated | request.sent
  | waf.blocked | verdict.ready | degraded | task.terminated | heartbeat

VerdictSource: RULE | SEMANTIC | FUSION        ← 报告里要区分，别漏
```

**谈枚举的三个纪律**：
1. **一律大写下划线英文，不用中文、不用数字**（数字枚举一改就全线崩）；
2. **前端对未知枚举必须容错**（显示"未知状态: XXX"灰标签），不白屏——这条保护你不被"1 号加了个新值"打死；
3. **加值 = L2 变更（允许）**，改语义 = L3 变更（禁止）。

#### F. 错误码（必须区分"超时"和"降级"）

| code | HTTP | 含义 | 大屏/前端应表现 |
|---|---|---|---|
| 0 | 200 | 成功 | — |
| 40001 | 400 | 参数非法 | 表单红字 |
| 40002 | 400 | 未勾选授权确认 | 弹窗挡住，不能提交 |
| 40301 | 403 | 目标不在授权 scope 内 | 明确告知"不在授权范围"，不透露 scope 内容 |
| 40401 | 404 | task/round 不存在 | 空态页 |
| 40901 | 409 | 幂等冲突（已存在，返回既有） | 静默接受，不报错 |
| 40902 | 409 | 超出并发上限（已有活跃任务） | "有任务在跑，已排队" |
| 42201 | 422 | 引擎返回不符合契约 schema | "引擎输出异常，已记录" |
| 42901 | 429 | 靶场侧限流 | "节奏受限，自动退避" |
| 50001 | 500 | 引擎内部错误 | 失败态 + trace_id |
| 50301 | 503 | **模型熔断打开（降级）** | **黄色 DEGRADED 角标**，不是红色错误 |
| 50401 | 504 | 单轮超时 | "本轮超时"标记，继续下一轮 |

> `50301` 与 `50401` 分开这一点很值钱：**降级不是故障，超时不是失败**。大屏把这两个混成一个红色 error，会把"工程稳健"演成"系统崩了"。

| `verdict_source` | 引擎 | 4 号 / 报告 | 报告"判定来源：规则/语义/融合" |
| `evidence_refs` | 引擎 | 4 号 / 报告 | **报告每条结论后的 `[第N轮]` 可点回链接** |
| `cost_ms` / `started_at` / `ended_at` | 引擎 | 4 号 / 前端 | 大屏耗时、证据链时间轴、报告附录 |
| `fallback_used` / `degraded_flag` | 引擎 | 4 号（**落库+SSE+报告三处同步**） | **大屏 DEGRADED 角标**、报告"降级轮次单列" |
| `adapter_name` | 引擎 | 4 号 / 实验统计 | 报告"实验配置"、证据链 |
| `terminate_reason` | 引擎（命中）/ 4 号（其余） | 4 号 / 前端 | 大屏终止提示、历史列表、报告 |
| `trace_id` | 4 号（网关） | 全链路日志 | 错误页"请提供 trace_id"，**联调定位的命根子** |

### 3.4 契约冻结的推进话术（三句话，照念）

1. **开场**："我把 10 个接口都按我的理解填满了，你不用从零设计，只需要看哪里不对，改一个字也行。"
2. **卡住时**："这个字段现在定不下来没关系，我们先约定**字段名和类型**，值域你后面给我，我按字符串存，你给了枚举我再收窄。"
3. **收尾**："我们从现在起只加字段、不改语义。你以后想改结构，提前一天告诉我，我出兼容方案，我们不发版。"

### 3.5 契约冻结的落地形式（别只停在口头上）

- 文档头部写死三行：`contract_version: 1.0` / `frozen_at: <相对描述，如"第一周末">` / `双方确认：1 号 ✓ 4 号 ✓`；
- 所有接口响应里带 `contract_version`（放进统一包壳），你**看一眼就知道对面是不是旧版本**；
- 建 `docs/contract-changelog.md`，每次变动一行：`日期 | 版本 | 变更类型(L0/L1/L2/L3) | 字段 | 影响面 | 谁改的`；
- **L3 变更（改语义）必须三方会**（1 号、4 号、架构师），不许在群里一句话改了。

## 第四章 数据库落地：以 `round` 为主轴

### 4.1 设计原则（三条，先认下来）

1. **`round` 是主轴**：其余表全部通过 `round_id` 挂载。任何一条记录都要能回答"我属于哪一轮"。拼不出时间线的表设计，等于没有证据链。
2. **默认脱敏、默认不存原始凭据**：`desensitized` 是**字段**，不是口头约定。
3. **`model_decision.raw_output` 必须原样保存**（含格式漂移的非法输出）。非法输出是"小模型不稳定"这一真实短板的证据，也是你降级设计可信度的来源。**把它删干净，反而显得像摆拍。**

### 4.3 索引怎么建（每一条都有明确查询支撑）

| 索引 | 支撑的查询 | 为什么要它 |
|---|---|---|
| `uk_task_round (task_id, round_no)` | 幂等写入、单轮定位 | **唯一键即幂等键**，这一条防住"重复轮次"这个高频事故 |
| `idx_task_seq (task_id, round_no)` | `GET /rounds` 分页、时间线渲染 | 覆盖查询，按序返回不用 filesort |
| `idx_group_round (group_tag, round_no)` | 收敛曲线聚合：`SELECT group_tag, round_no, AVG(...) GROUP BY 1,2` | **一条索引支撑三份证据里的曲线**，1 号出图前会来查这个 |
| `idx_status_created (status, created_at)` | 调度器扫活跃任务、历史页列表 | 状态机扫描必须走索引，别全表扫 |
| `idx_task_hit (task_id, hit_signal)` | 结果页"只看命中轮" | 命中轮通常是少数，走索引快 |
| `idx_round (round_id)` 于 4 张子表 | 证据链按轮装配 | **证据链是 N 表 join，子表没索引会慢成幻灯** |
| `uk_client_req (client_request_id)` | 建任务防重复提交 | 双击提交只建一个任务 |

**不要建的索引**：`waf_signal.redacted_snippet` 全文索引（用不上）、`round.state_in_digest` 上的 JSON 索引（只读展示，不筛选）。**索引不是越多越好，一个用不上的索引就是一次写入开销。**

### 4.4 哪些字段绝对不要存（合规 + 体积双重要求）

| 不存的东西 | 为什么 | 替代方案 |
|---|---|---|
| `Cookie` / `Set-Cookie` / `Authorization` / `X-Api-Key` / 任何 Token | 一旦入库并导出，合规质疑一问就穿 | 替换为 `<REDACTED:credential>`，只记"存在该头" |
| **完整原始响应体** | 会含业务数据；也把 DB 撑爆 | 只存 `response_fingerprint`（sha256）+ `response_length` + 脱敏片段 ≤2048 |
| **完整原始请求头** | 大头是无关头，且常带凭据 | 只存白名单头：`Host/User-Agent/Content-Type/Content-Length` |
| **明文完整载荷** | 既是敏感内容，也是"可复用"风险 | 只存 `operator_chain`（算子编号）+ `param_ref` + 脱敏片段 |
| 真实目标域名/IP | 材料不得出现真实站点 | 存 `target_url` 但报告里只出 `target_alias`（如 `lab-target-01`） |
| 用户账号密码 / 会话 ID | 完全无关 | 不采集 |
| 完整 `history_summary` | 会随轮次膨胀 | `VARCHAR(2000)` 硬截断，截断标记入 `detail` |

> **实现要求**：脱敏必须收敛到**一个函数** `sanitize(record, rule_version) -> record`，在 `HttpClient` 返回后、入库前**唯一一处**调用。任何绕过这个函数的写入路径，视为代码评审阻断项。**因为"某处忘了脱敏"是这类系统最常见的合规事故，而它无法靠人工审查防住，只能靠单点收敛。**

### 4.5 留存与清理（落到字段上）

| 数据 | 留存期（假设，可配） | 配置项 | 清理动作 |
|---|---|---|---|
| `round` / `payload_attempt` / `waf_signal` / `model_decision` | 30 天 | `RETENTION_DAYS_ROUND=30` | 先归档 JSON 再删 |
| `finding` | 90 天 | `RETENTION_DAYS_FINDING=90` | 保留结论，清 `evidence_round_ids` 无效引用 |
| 导出报告文件 | 7 天 | `RETENTION_DAYS_REPORT=7` | 删文件 + 软删记录 |
| `audit_log` | 180 天 | `RETENTION_DAYS_AUDIT=180` | **不删**，删除动作本身要写审计 |

清理入口必须**手工可触发 + 有审计**：`python -m app.tools.purge --older-than 30d --dry-run`。先 `--dry-run` 打印影响行数，再执行。**删除操作写 `audit_log`，但没有"一键清空"按钮**——现场误点清空是能毁掉整个答辩的事故。

### 5.1 单活跃任务：两层保护，别只靠内存

```python
# 层 1：进程内信号量（快，但多 worker 时无效）
ACTIVE = asyncio.Semaphore(int(os.getenv("MAX_ACTIVE_TASKS", "1")))

# 层 2：DB 兜底裁决（慢但权威）——抢一个"活跃槽"
async def acquire_slot(conn, task_id: str) -> bool:
    async with conn.cursor() as cur:
        await cur.execute(
            "SELECT task_id FROM task WHERE status IN "
            "('PARAM_COLLECTING','ITERATING') AND task_id<>%s LIMIT 1", (task_id,))
        return (await cur.fetchone()) is None   # 无人在跑才放行
```

要点：
- **默认单活跃任务**（`MAX_ACTIVE_TASKS=1`）。这不是性能妥协，是**靶场保护 + 对比公平性**双重要求：多任务并行会把同机的 DVWA+ModSecurity 打挂，演示当场失去被测对象。
- 超限时**不要拒绝**，返回 `40902` + "已排队"，任务保持 `CREATED`，由调度器轮转启动。现场被评委点两次"开始"是很常见的，直接报错很尴尬。
- 进程内信号量只作为快速路径，**DB 是权威**。理由是：你重启一次后端，信号量就归零了，但 DB 里可能还有一个 `ITERATING` 的僵尸任务——**必须能被新进程识别出来并标记 `FAILED`**（启动时做一次 reconcile）。

### 5.2 幂等：唯一键就是幂等键，不要发明新机制

```python
INSERT_ROUND = """
INSERT INTO round (round_id, task_id, round_no, param_ref, started_at, group_tag, mock_flag)
VALUES (%s,%s,%s,%s,%s,%s,%s)
ON DUPLICATE KEY UPDATE round_id = round_id   -- 空更新：已存在即视为成功，不改任何业务字段
"""
async def upsert_round(conn, rec: dict) -> str:
    await conn.execute(INSERT_ROUND, (rec["round_id"], rec["task_id"], rec["round_no"], ...))
    async with conn.cursor() as cur:
        await cur.execute("SELECT round_id FROM round WHERE task_id=%s AND round_no=%s",
                          (rec["task_id"], rec["round_no"]))
        return (await cur.fetchone())[0]
```

要点：
- **幂等键必须是 `(task_id, round_no)`**，绝对不能是"随机 uuid"或"时间戳"。用 uuid 做幂等键等于没有幂等——每次重试都插一条新记录，你的证据链里就会出现两条"第 3 轮"，评委一看就废。
- `ON DUPLICATE KEY UPDATE round_id = round_id` 是**空更新技巧**：既触发幂等分支，又不覆盖已落库的业务字段（覆盖会丢掉第一次的真实结果）。
- 回调接口（契约 5）和单轮接口（契约 4）**走同一个 `upsert_round`**，因为异步模式下两条路径都可能先到。
- 重试只针对**网络抖动**（连接失败、5xx 且无响应体）。**同一 `(task_id, round_no)` 永不重复发包**——重复发包会被靶场/WAF 记为异常流量，也可能让 1 号误判"收敛"。

### 5.3 SSE：断线续传 + 心跳 + 轮询降级

```python
@router.get("/api/v1/tasks/{task_id}/events", response_class=StreamingResponse)
async def events(task_id: str, request: Request,
                 last_event_id: str | None = Header(default=None, alias="Last-Event-ID")):
    async def gen():
        seq = int(last_event_id or 0)                 # ★ 断线续传起点
        yield "retry: 3000\n\n"                       # 告诉浏览器 3s 后重连
        while True:
            if await request.is_disconnected():
                break
            evts = await hub.fetch_after(task_id, seq, limit=50)   # 内存环形队列 / DB
            for e in evts:
                seq = e.seq
                yield f"id: {e.seq}\nevent: {e.name}\ndata: {e.json()}\n\n"
            if not evts:
                yield ": ping\n\n"                    # ★ 心跳（注释行，不入 data）
            await asyncio.sleep(0.5)
    return StreamingResponse(gen(), media_type="text/event-stream", headers={
        "Cache-Control": "no-cache",
        "Connection": "keep-alive",
        "X-Accel-Buffering": "no",                    # ★ 破 Nginx 缓冲
    })
```

**五个必须做到的点**：

1. **`id:` 必须单调递增且持久**。用 `round_no*100 + 事件序号`，或用全局自增 `seq` 存表/内存队列。前端重连时浏览器自动带 `Last-Event-ID`，你从 `seq+1` 继续推——**"不重不漏"是 SSE 体验的分水岭**。丢了事件，大屏就会缺一轮，评委正好抽那一轮。
2. **心跳 `: ping`（注释行，冒号开头）**。15s 一次。作用有三：防反向代理 60s 超时断连、让前端能判断"连接活着"、**在 `slow` 模式下让画面有微动，不至于被看成死机**。
3. **`X-Accel-Buffering: no`**。这是 SSE 最经典的坑：Nginx/若干 PaaS 默认缓冲响应体，事件会被攒着批量下发，表现为"前端 30 秒后一次性刷出 20 条"。加了这行还不够，部署时 Nginx 侧也要 `proxy_buffering off;` + `proxy_read_timeout 3600s;`。
4. **轮询降级路径必须存在且能自动触发**。前端 `EventSource.onerror` 连续失败 3 次 → 切到 `GET /tasks/{id}` 每 2s 轮询（只拿 `status/current_round/last_event`，**不要轮 `GET /rounds`**）。为什么必须有：比赛现场的网络是你控制不了的，而"大屏空白"比"数据略慢"严重得多。
5. **不要在 SSE 端点里做同步 DB 查询**。FastAPI 是 async 的，同步 DB 调用会阻塞整个事件循环，表现为"一个客户端订阅后，全站变慢"。要么用 async 驱动，要么 `await asyncio.to_thread(...)`。

**`hub.fetch_after` 的实现取舍（假设单进程）**：内存里维护 `dict[task_id, deque(maxlen=2000)]`，SSE 从内存取；同时**每条事件已经落库**，所以内存丢了也能从 `round` 表重建。这个"内存加速 + DB 兜底"的组合最省事，不需要 Redis。

### 5.4 授权 scope 中间件：三道门，全在服务端

```python
def assert_authorized(body: dict) -> None:
    # 门 1：授权确认必须是真值（不信前端）
    if body.get("authorization_confirmed") is not True:
        raise ApiError(40002, "必须确认已获得目标书面授权")
    if not (body.get("authorization_id") or "").strip():
        raise ApiError(40002, "authorization_id 不能为空")
    # 门 2：目标必须落在 scope（精确 host 匹配，不做通配/后缀）
    u = urlparse(body["target_url"])
    if u.scheme not in {"http", "https"} or not u.hostname:
        raise ApiError(40001, "target_url 非法")
    if u.hostname.lower().rstrip(".") not in {h.lower().rstrip(".")
            for h in body.get("scope", {}).get("hosts", [])}:
        raise ApiError(40301, "目标不在授权 scope 内")
    # 门 3：禁止跟随到 scope 外的重定向（逐跳校验，最多 3 跳）
    if body.get("follow_redirects") is True and not body.get("_redirect_same_scope_only"):
        raise ApiError(40001, "仅允许同 scope 内重定向")
```

要点：
- **三道门缺一不可**：确认位（意愿）+ scope（范围）+ 重定向（范围逃逸的常见漏洞）。**第二道门最容易被绕过**：如果你允许 `*.example.com` 后缀匹配，那这个校验形同虚设。
- **精确匹配，不做通配**。理由：通配会把"授权一个测试站"变成"授权整个域"。宁可让用户多填几个 host，也不要扩大授权面。
- 创建成功时把 `authorization_id / authorized_by / authorized_at / scope` **落 `task` 表**，并写一条 `audit_log(action='TASK_CREATE')`。这四行数据是答辩时"授权可追溯"的实物证据。
- 取消、导出也各写一条 `audit_log`。**导出尤其重要**——报告含"成功绕过"结论，谁导的必须可查。

### 5.5 报告唯一入口：一个 Service，一条路径

```
POST /api/v1/reports  →  ReportService.create(task_id, opts)   ← 全系统唯一生成器
                          ├─ 校验 task.status ∈ {TERMINATED, REPORTED}（运行中拒绝）
                          ├─ 读 round + payload_attempt + waf_signal + model_decision + finding
                          ├─ 走 sanitize() 二次确认（防历史脏数据）
                          ├─ 渲染 HTML 模板 → 转 PDF（见第七章）
                          ├─ 加水印 / 使用范围声明 / task_id
                          └─ 落文件 + report 记录 + audit_log(REPORT_EXPORT)
```

**"唯一入口"的实际含义**：前端**不允许自己拼报告**、**不允许前端直连渲染库**、**不允许有第二个 `/export` 端点**。理由很实在——两套模板必然产生两个版本的报告，答辩现场导出的是旧那版，讲的却是新那版，这是灾难。前端只做两件事：**调 `POST /reports`** + **用 iframe 展示返回的 `download_url`**。

**在线预览 = 同一份模板**。做到这一点的技巧：后端除了出 PDF，还提供 `GET /reports/{id}/html`，返回同一份渲染结果（只是没转 PDF）。前端 iframe 直接嵌它。**预览与导出同源，就永远不会出现"预览好好的，PDF 里表格错位"这种现场事故。**

### 5.6 超时终止与 `terminate_reason` 的归属

```
谁写 terminate_reason：
  引擎给的（命中类）  : HIT / CONVERGED / MODEL_FALLBACK_EXHAUSTED / NO_PARAM
  调度器给的（治理类）: TIMEOUT / BUDGET_EXHAUSTED / MAX_ROUNDS / CANCELLED / ENGINE_ERROR
  ★ 规则冲突时：引擎已给出的不被调度器覆盖；调度器只在"引擎没给"时写入。
```

实现要点：

- **双层超时**：单轮 `timeout_ms`（引擎内）+ 任务级 `budget_ms`（调度器看门狗）。看门狗每 2s 扫一次 `task` 表里 `elapsed_ms` 超预算的记录，置 `TERMINATED` + `TIMEOUT`/`BUDGET_EXHAUSTED`。
- **超时必须走"正常终止路径"**：写 `terminate_reason` → 推 `task.terminated` SSE → 允许导出报告。**不要让超时变成"请求挂了、状态卡在 ITERATING"**——那会让大屏永远转圈，而且报告导出会因"任务未终止"被拒（你自己的校验会把自己卡死）。
- **取消接口必须幂等**：已终止的任务再取消，返回当前状态 200，不报错。
- **MAX_ROUNDS 意味着"未收敛"**，报告里必须如实写"达到轮次上限，未收敛"，**不能算作成功**。这是架构明确的诚信约束，也是你报告模板里要硬编码的一段文案。

### 5.7 靶场侧限流与模型熔断（很短的代码，很救命的功能）

- **靶场限流**：同一 `param_ref` 相邻两轮最小间隔（假设 800ms，可配 `MIN_ROUND_INTERVAL_MS`），用 `asyncio.Lock` + 上次时间戳。目的：不打垮靶场，也让大屏的节奏"看起来像在思考"而不是疯狂刷屏。
- **模型熔断**：连续 `M=3` 次失败/超时 → 打开熔断 60s → 期间所有轮 `degraded_flag=true`、`fallback_used=true`、`adapter_name` 记实际兜底适配器 → 半开探测一次成功则关闭。**熔断状态必须是可查询的**（契约 8 `/health/model` 返回 `circuit_state`），因为大屏要显示它。

### 5.8 统一响应包壳与 `trace_id`

```python
def ok(data, trace_id): return {"code": 0, "data": data, "message": "ok",
                                "trace_id": trace_id, "server_time": utcnow_iso(),
                                "contract_version": CONTRACT_VERSION}
```

- **`contract_version` 放进每个响应**。联调时你只要看一眼这个值就知道对面是不是旧版本——**这一行能省你半天排查**。
- `trace_id` 从入口生成，写进日志 + 所有下游调用 + 数据库 `detail`。前端错误页显示它，跟 1 号对话时直接说"给我 trace_id 为 xxx 的日志"。
- 时间**一律 ISO 8601 UTC**，带毫秒和 `Z`。前端统一用一个 `fmtLocal()` 转本地。**时区不一致是证据链最阴的坑**（见第十章）。

## 第六章 前端 5 个页面的开发顺序与取舍

### 6.1 开发顺序（按"谁离答辩最近"排，不按用户流程排）

| 顺序 | 页面 | 为什么这个顺序 | 最小可用形态（MVP） |
|---|---|---|---|
| **1** | **大屏监控** | **答辩主舞台**。而且它会倒逼你把 SSE、事件语义、轮次数据全部打通——先做它，等于先把最难的数据链路啃下来 | 单页纵向时间线：轮次卡 + 4 色标签 + 策略卡 + 降级角标；顶部状态条 |
| **2** | **任务配置** | 大屏要有数据源，得先能建任务。而且授权勾选是 P0 合规项，越早做越不会被返工 | 表单（URL/漏洞类型/分组/轮次）+ **授权确认必选** + 提交后跳大屏 |
| **3** | **漏洞结果** | 答辩第二问必是"证据链在哪"。这页就是证据链的呈现 | 轮次表格 + 点开抽屉看六要素 + "只看命中"筛选 + 导出 JSON 按钮 |
| **4** | **报告预览** | 需要 PDF 方案先跑通，所以排第 4 | iframe 预览 + "导出 PDF" 按钮 + 水印提示 |
| **5** | **历史记录** | 最简单、最不决定成败，可以最后做甚至做最简版 | 表格：时间/目标别名/分组/状态/轮次/结论/操作（查看/导出） |

**为什么大屏排第一**：如果按"配置→大屏→结果"的用户流程做，你会先花时间在表单校验这种低价值高琐碎的事情上，等做到大屏时时间已经被压缩，而大屏恰恰是**唯一能让评委直观看到"AI 在干活"的窗口**。反过来做，即使结果页最后很素，答辩照样成立。

### 6.2 大屏必须显示的 5 样东西（缺一不可）

| # | 元素 | 具体内容 | 为什么不能少 |
|---|---|---|---|
| **1** | **轮次计数器** | `第 3 轮 / 上限 8 轮`，大字 + 剩余预算 | 评委第一眼要判断"这是多轮迭代还是在跑字典"。**数字在跳，就是自适应** |
| **2** | **当前变形策略** | `strategy_tag` + `rationale` 一行 + 算子序列（如 `OP_ENC_SEQ_2`） | 证明"每一轮载荷不一样、且不是随机"。这是"AI 在决策"最直接的证据 |
| **3** | **WAF 拦截四色标记** | `BLOCKED`（红）/ `ANOMALY`（橙/绿）/ `NORMAL`（灰）/ `TIMEOUT`（黄）| **评委最想看的一格**。红→绿的颜色转变，就是"绕过成功了"的视觉转译 |
| **4** | **模型决策摘要** | `adapter_name` + 上轮依据（"依据第 2 轮：拦截特征 RULE_KEYWORD_B"）+ 本轮策略标签 | 体现"本轮由上轮响应驱动"——这是与 sqlmap tamper 的本质分野，**必须肉眼可见** |
| **5** | **降级角标** | `DEGRADED` 黄色角标，附 `fallback_used` 说明 | 诚信标记。**主动显示降级，比藏起来更能加分** |

**可选的第 6 样（有则更好）**：顶部一条"事件流水"横向滚动条（`round.started → payload.generated → request.sent → waf.blocked`），让画面有持续运动感。

### 6.3 事件怎么驱动刷新（含节流）

```
收到 SSE 事件（只含轻字段）
   ├─ 立刻更新"轻状态"：轮次计数、四色标签、当前策略、时间戳（纯本地，0 网络）
   └─ 打一个 200ms 节流标记 → 触发 GET /rounds?from_round=<当前最大轮次-2>
        └─ 拿到完整轮次详情 → 合并进列表（不整表重渲染，按 round_no 做 diff）
```

三条纪律：

1. **事件里不塞大字段**，大字段一律拉取。否则断线重连时你要重放几十条含 `model_decision_raw` 的事件。
2. **必须节流**。同一轮会连发 5 个事件，不去重就是一轮拉 5 次详情。
3. **`from_round` 只拉最近 3 轮**。大屏不需要历史全量，需要的是"当前在干什么"。

### 6.4 如何避免"静止画面看起来像死机"（这一条决定答辩印象）

本地小模型单轮推理可能慢到评委明显等待（架构第 4 节已提示，具体数值须现场实测）。静止 30 秒的大屏 = 评委认为系统挂了。**五个手段组合使用**：

| 手段 | 实现 | 效果 |
|---|---|---|
| **服务端心跳事件** | 15s 一次 `heartbeat` | 数据层"活着"的证据 |
| **前端本地计时器** | 每秒 tick 一次"本轮已等待 12.4s" | **不依赖后端**的持续变化，最可靠 |
| **呼吸灯 / 骨架屏** | "模型思考中…" 三个点循环 | 视觉上的"进行中" |
| **连接状态灯** | 绿（已连接）/ 黄（重连中，已重连 2 次）/ 红（已断开，切轮询） | **顺便把断线重连演成可靠性展示** |
| **最后事件时间戳** | 右上角常驻"最后更新 00:03:12" | 评委自己能判断是"慢"还是"死" |

**加一个硬规则**：前端若 20s 内未收到任何事件且任务状态是 `ITERATING`，显示横幅"引擎响应较慢，正在等待（已等待 Ns）"，**不要显示错误、不要清空画面**。慢不是错，空白才是。

### 6.5 每个页面明确"不做什么"（这是省时间的关键）

| 页面 | 砍掉 | 理由 |
|---|---|---|
| 大屏 | 图表库、动画库、多主题、音效、粒子效果 | 用原生 CSS + 简单 SVG 曲线就够；动画库只会拖慢首屏 |
| 任务配置 | 高级选项折叠面板（seed/temperature/prompt_version 等）、多目标批量、爬虫深度配置 | 这些字段有默认值就够；现场演示不会去调 seed |
| 漏洞结果 | 复杂筛选器、自定义列、批量操作、虚拟滚动 | 一个 `只看命中` 开关 + 一个表格足够 |
| 报告预览 | 多模板切换、在线编辑、分享链接 | **唯一模板 + 一个导出按钮**。多模板是 P2，可直接砍到答辩后 |
| 历史记录 | 时间范围选择器、分面搜索、导出历史 | 表格 + 状态筛选 + 分页三个够用 |

**P2 一律砍掉**：UI 动效精修、多主题、图标体系、深浅色切换。产品经理已经明确这是 P2。

### 6.6 前端三个技术底线

1. **未知枚举必须容错**。所有枚举渲染走一个 `renderEnum(value)`，未知值输出灰色"未知: XXX"。**绝不白屏**。这一条保护你免于"1 号加了个新枚举值"导致的现场事故。
2. **所有请求走同一个 `apiClient`**：统一注入 `trace_id`（前端也能生成，方便对齐）、统一解析 `{code,data,message,trace_id}`、统一处理 `40301/40002/50301` 三类特殊码。
3. **`EventSource` 不能自定义 Header**——这是硬限制。如果 SSE 端点需要鉴权，用 **Cookie**（同源自动带）或 **query 参数 token**。**不要在 SSE 上做 Bearer Header 鉴权，它根本发不出去**，这是一个能让人卡一整天的坑。

## 第七章 PDF 报告方案

### 7.1 三条技术路线对比

| 维度 | **A. 后端 HTML 模板 + 无头浏览器** | **B. 后端模板直出（WeasyPrint / ReportLab）** | **C. 前端生成（jsPDF / html2canvas）** |
|---|---|---|---|
| 技术形态 | 渲染 HTML/CSS → Chromium 打印 PDF | 用 Python 库直接绘制/排版 | 浏览器里截图/绘制再下载 |
| 中文支持 | 随镜像装字体即可，最省心 | 需配字体文件，WeasyPrint 尚可，ReportLab 要手工注册 | 依赖系统字体，跨机器不一致 |
| 排版可控性 | **最高**（CSS + `@page` 分页、页眉页脚、页边距） | 中（分页要手写，表格跨页易出错） | 低（长文分页基本失控） |
| 复杂表格 | **强**（HTML table，跨页自动断开） | 一般（需手工计算分页） | 弱 |
| 预览一致性 | **与在线预览同源**（同一个 HTML） | 需另做一套 HTML 预览 | 与预览天然同源，但两边都不可靠 |
| 部署成本 | 中偏高（Chromium 体积大，约百 MB 级；依赖系统库） | **低** | **最低**（纯前端） |
| 生成耗时 | 中（首次启动浏览器较慢） | 低 | 低 |
| 出错可控性 | 好（后端有完整日志） | 好 | 差（用户机器差异大） |
| 适合本项目的程度 | **推荐** | 备选 | 不建议 |

### 7.2 推荐结论：走 A（后端 HTML + 无头浏览器），B 作为部署包瘦身时的备选

**理由（按重要性排序）**：

1. **预览与导出必须同源**。你要做"在线预览 + 导出"，如果两条链路用两套技术，必然出现"预览好好的、PDF 里表格错位"。A 方案天然解决——`GET /reports/{id}/html` 与 `POST /reports` 用同一份模板，只差最后一步打印。**这是 A 相对 B 的决定性优势。**
2. **证据链是一堆长表格**（逐轮表、拦截特征表、模型决策表），**跨页分页是刚需**。CSS 的 `@page` + `thead` 重复 + `break-inside: avoid` 让分页几乎零成本；B 方案要手工算每页能放几行，一改行高就崩。
3. **中文字体可控**。把思源黑体（或任一开源中文字体）的子集打进部署包/镜像，字体就永远对。**C 方案在别人机器上大概率乱码或回退成奇怪字形**，而"报告打开是方块"在答辩现场是致命的。
4. **部署成本可接受**。虽然无头浏览器体积大，但**你的部署包本来就要装 MySQL + 靶场 + 模型**，多一个 Chromium 不是量级变化。反过来，如果部署包体积是硬约束（比如要塞进 U 盘/离线分发），**退回 B**，但要接受"分页要手写"的代价。

**A 方案的工程约束（必须遵守）**：
- 浏览器实例**常驻复用**（启动一次，`newPage`/`close` 复用），**不要每次导出都启动浏览器**——那样一次导出会慢到现场无法接受；
- 导出**异步化**：`POST /reports` 返回 `202 + report_id`，前端轮询 `GET /reports/{id}` 拿 `download_url`；
- **加并发上限**（假设 1 个并发导出），超限排队。多个导出同时跑会把内存打满；
- 导出失败必须**保留已有文件不删**，并提供"重试"按钮。

### 7.3 脱敏、水印、可溯源怎么实现

**① 脱敏（默认开启，不可关闭）**

```python
# 报告渲染前二次确认：历史脏数据也可能带凭据
def ensure_sanitized(round_rec: dict) -> dict:
    for k in ("redacted_request", "redacted_response"):
        if not round_rec.get(k) or round_rec.get("desensitized") != 1:
            raise ReportError("存在未脱敏记录，拒绝导出", trace_id=...)
    return round_rec
```

- `POST /reports` 的 `desensitize` 参数**只接受 true**（传 false 返回 40001）。**"允许导出未脱敏"这个开关本身就不该存在**，因为迟早会有人在现场把它打开。
- `include_raw_evidence` 默认 `false`。开了也只是包含 `redacted_*` 与 `model_decision_raw`（模型原文不含凭据，可放），**永不含原始 Cookie/Token**。
- 报告首页固定三段声明：① "本报告仅限授权范围内使用"；② "演示/测试环境说明"（如"本地隔离靶场"）；③ 授权 ID 与授权时间。

**② 水印**

| 层 | 实现 | 备注 |
|---|---|---|
| 页面水印 | CSS `position: fixed` 的重复斜排文本 `task_id` + 生成时间，`opacity: 0.08` | 用 `@media print` 保证每页都有 |
| 页眉 | 每页顶部 `task_id` 短哈希（后 8 位）+ "仅限授权范围内使用" | `@page` margin box 或 `thead` 重复 |
| 页脚 | `第 X / Y 页` + 生成时间（UTC + 本地双写） | 便于评委核对"是不是同一版" |
| 元数据 | PDF `Subject/Keywords` 写 `task_id` | 便于事后检索与分发追踪 |

**③ 证据链可溯源（核心要求：每条结论能点回 `round_id`）**

报告结构必须这样做：

```
第 4 章 探测结论
  4.1 SQL 注入（参数 id）  结论：存在漏洞  置信度 0.91  判定来源：规则+语义融合
      ▸ 证据轮次：第 3 轮（round_id: 01J...R03）  ← 打印可见的锚点
      ▸ 依据：第 1、2 轮被 WAF 拦截（RULE-LAB-007 / -011），第 3 轮变形后响应分类为 ANOMALY

附录 A 逐轮执行记录（表格，每行一轮）
  | 轮次 | round_id | 依据上轮 | 变形策略 | 校验 | 响应分类 | 结论 | 耗时 |
  |  1   | 01J...R03|   —      | OP_BASE  | 通过 | BLOCKED  | 未发现 | 5.2s |
  ...

附录 B 模型决策原文（每轮一段，等宽字体，原样保留）
  第 1 轮  adapter=OllamaAdapter  prompt=p3  schema=s2  valid=true
  ---- 模型原文开始 ----
  ...
```

**"可溯源"的判定标准**：PDF 是纸，不能真的点击。所以要求是——**报告正文里出现的每一个 `round_id`，都能在附录 A 表格里找到同一行；附录 A 的每一行，都能在 `GET /rounds` 与导出 JSON 里找到同一条记录。** 三处 ID 一致，溯源就成立。**这是"怎么证明不是硬编码"的书面证据**，答辩时要能当场演示这条链路。

**④ 报告里必须如实写的一段（模板硬编码）**

> 本次探测在轮次上限内/外终止，终止原因：`{terminate_reason}`。其中 `{n}` 轮因模型降级使用兜底策略（`degraded_flag=true`），该部分轮次不计入主实验成功率统计。本报告结论仅适用于 `{scope}` 授权范围内的 `{target_alias}`。

这段话不好看，但它是**评审最信的那种诚实**。

### 7.4 报告内容清单（最小版，10 节以内）

1. 封面（任务 ID / 目标别名 / 生成时间 / 授权信息 / 使用范围声明）
2. 执行摘要（跑了几轮、终止原因、结论一句话）
3. 测试范围与授权信息
4. 探测结论（每条带 `evidence_round_ids`）
5. 闭环过程概览（轮次—响应分类表 + 简图）
6. 逐轮详情（含模型决策原文，可折叠/附录化）
7. 降级与异常说明（`degraded_flag` 轮次单列、超时轮次单列）
8. 附录 A 逐轮执行记录
9. 附录 B 模型决策原文
10. 附录 C 配置快照（`group_tag` / `adapter_name` / `max_rounds` / `seed` / `prompt_version` / WAF 规则集版本）

**第 10 节别省**。它证明了"可复现"，也是消融实验可对比的依据。

## 第八章 联调与防返工

### 8.1 契约桩 → 真引擎：切换步骤（30 分钟的事，不要搞成一天）

| 步 | 动作 | 通过标志 |
|---|---|---|
| 1 | 确认对面 `GET /api/v1/health/model` 返回 `loaded=true` | 有正常响应 |
| 2 | `ENGINE_MODE=http`，`ENGINE_BASE_URL` 指向真引擎 | 服务能启 |
| 3 | **单轮试跑**：手工调一次 `execute_round`，把返回 JSON **逐字段**比对契约 | 字段名/类型/枚举值 100% 一致，或差异清单 ≤5 条 |
| 4 | 差异逐条定性：L1 加字段（忽略）/ L2 加枚举值（前端容错）/ L3 改语义（**停下来开会**） | 有一条 L3 就不许继续 |
| 5 | 同一任务 mock / http **双跑**，两份 `GET /rounds` 并排比结构 | 结构一致，仅数据值不同 |
| 6 | 跑完整任务，检查大屏 8 类事件是否都出现 | 8/8 出现，无缺失 |
| 7 | 检查 `degraded_flag` 路径：临时停掉模型服务，看是否降级而非崩溃 | 出现黄角标 + 任务继续 |
| 8 | 检查 `terminate_reason`：HIT / MAX_ROUNDS 两条路径都跑到 | 两条都有 |

**切换失败的兜底**：`ENGINE_MODE=mock` 一行改回去，产品立刻回到"可演示"状态。**这就是契约桩最大的价值——它让你的系统永远有一个能跑的状态**，而不是"1 号改崩了全队停摆"。

### 8.2 联调检查清单（逐条打勾，一条不过不许宣布"联调完成"）

- [ ] 建任务必须勾授权，不勾返回 `40002`；
- [ ] 目标不在 scope 返回 `40301`，且响应体**不泄露** scope 内容；
- [ ] 同一任务双击提交只产生一个 `task`；
- [ ] `(task_id, round_no)` 重复下发不产生两条 `round`；
- [ ] 每轮 5 类事件（started/generated/sent/blocked or verdict/终止）都出现；
- [ ] 断线重连后轮次**不重不漏**（用 `MOCK_TICK=slow` + 手工断网验证）；
- [ ] 任取一轮能回答五问（第几轮/依据上轮/模型原文/校验/结论耗时）；
- [ ] 导出 JSON 证据链能被非开发人员读懂（找 2 号验）；
- [ ] PDF 中文正常、水印在每页、无原始凭据；
- [ ] 停掉模型服务 → 降级角标出现、任务不崩、报告标注降级轮次；
- [ ] 任务超时 → `terminate_reason=TIMEOUT`，能导出报告；
- [ ] 并发建 3 个任务 → 1 个跑、2 个排队，靶场不挂；
- [ ] 所有时间显示一致（DB / 日志 / 大屏 / PDF 四处的同一事件时间戳对得上）。

### 8.3 字段对不上时，按这个顺序定位（不要瞎猜）

```
① 先看 contract_version
   ├─ 响应里 version ≠ 你期望的  → 对面是旧版本，直接找 1 号对齐版本，别查代码
   └─ version 一致 → 下一步
② 再看 trace_id 对应的服务端日志
   ├─ 日志里 raw_body 与契约一致 → 问题在你的解析层（字段名拼错/大小写/类型转换）
   └─ 日志里 raw_body 与契约不一致 → 问题在引擎侧，把 trace_id + raw_body 发给 1 号
③ 再看 DB 落库结果
   ├─ 库里对、接口返回不对 → 问题在序列化层（DTO 漏字段）
   └─ 库里就不对 → 问题在 upsert 语句（字段顺序/漏字段）
```

**为什么第一步是版本号而不是日志**：因为 80% 的"字段对不上"是版本不一致（对面还没重启、你连的是 mock、或者环境变量没生效）。**查版本号 5 秒，翻日志 15 分钟。**

配套要求：引擎客户端**必须保留最近 N 条完整请求/响应原文**（内存环形队列 100 条 + 落 `logs/engine_raw.log`，脱敏后），联调期这个日志救你无数次。

### 8.4 如何避免"最后一周返工"（五条硬规则）

| # | 规则 | 具体做法 |
|---|---|---|
| 1 | **只增字段不改语义** | 契约 L3 变更（改语义）需要三方会 + changelog；L1/L2 自由 |
| 2 | **前端对未知字段/枚举容错** | 忽略多余字段；未知枚举渲染灰标签。**这条能吃掉 90% 的"对面又加了东西"** |
| 3 | **枚举用字符串不用数字** | 数字枚举加一个值就可能错位，字符串最多显示"未知" |
| 4 | **每周一次 15 分钟契约同步** | 固定时间，只过 changelog，不讨论实现。有节奏的同步比偶尔的长会有效得多 |
| 5 | **代码冻结日** | 答辩前一周 `git tag release-candidate`，之后只允许 P0 bug 修复，新功能一律进 `post-release` 分支 |

**再加一条软规则**：**你的每个 P0 完成时，都要有一个"能独立运行"的验证方式**。比如"授权校验"要有 `curl` 命令、"证据链"要有导出 JSON 样例、"SSE"要有断网重连录屏。**能独立验证的东西不会返工，只能靠"整体跑一遍才知道对不对"的东西一定会返工。**

## 第九章 答辩现场保障（4 号视角，8 条）

> 格式统一为：**触发信号 → 4 号动作 → 观众看到什么**。核心思路：**把每个故障都演成一个设计特性**，而不是掩饰。

### ① 大屏预热（开始前 10 分钟）

- **触发信号**：距开场还有 10 分钟，大屏能打开但数据为 0。
- **4 号动作**：跑一个 `MOCK_TICK=fast` 的预检任务，确认 8 类事件全通；然后**保留一个已完成的真实任务**（含 3 轮以上），把大屏指向它，让画面处于"满载"状态；顺手把浏览器缩放定好、隐藏书签栏。
- **观众看到什么**：一进场大屏上就是一张有内容的、停在"已终止 / HIT"的完整过程图，而不是黑屏或"暂无数据"。**这 10 分钟的价值高于任何 PPT 动画。**

### ② SSE 断线自动重连

- **触发信号**：连接状态灯变黄/红；浏览器控制台出现 `EventSource` 重连日志；网络切换。
- **4 号动作**：什么都不用做——**前端已实现 3 次失败自动切轮询**，后端 `Last-Event-ID` 续传保证不重不漏。你只需要在讲稿里备一句"这里能看到它自己在重连"。
- **观众看到什么**：顶部黄条"连接恢复中…（第 2 次）"，3 秒后变绿，**轮次数字继续往后走、没有跳号也没有重复**。这一幕如果被看到，比全程无故障更能证明系统健壮。

### ③ 模型降级（DEGRADED）

- **触发信号**：`/health/model` 的 `circuit_state=OPEN`；大屏出现黄角标；`degraded_flag=true`。
- **4 号动作**：不要试图挽救、不要重启模型。让任务继续跑完，**主动指出角标**，并说一句"这是我们的降级链路在工作，此时用兜底策略集，这几轮不计入成绩"。
- **观众看到什么**：一个继续运转的系统 + 一个诚实的标注 + 一份把降级轮次单列的报告。**架构明确说过：降级必须可见，偷偷降级比崩溃严重。**

### ④ 导出失败 / 超时

- **触发信号**：`POST /reports` 超过 20s 未返回；或返回 500。
- **4 号动作**：点"重试"一次（多数失败是浏览器进程首次启动慢）；仍失败则打开**预生成的兜底 PDF**（F4 准备好的那份），并说明"这是同结构的样例报告，完整版我稍后下发"。
- **观众看到什么**：一个完整的报告版式在屏幕上，而不是一个转圈的按钮。**报告的内容可以晚到，版式不能缺席。**

### ⑤ 只跑单任务，避免打垮靶场

- **触发信号**：评委/主持人说"再跑一个"；或在已有任务运行时点了"开始"。
- **4 号动作**：不要放开并发。第二个任务进入 `CREATED` + 队列，大屏显示"已有任务运行中，本任务已排队（第 1 位）"。
- **观众看到什么**：一个明确的排队提示。你可以顺势讲一句"我们默认单活跃任务，这是为了保护被测靶场不被自己打垮，也保证对比实验公平"——**把限制讲成设计，是这类项目最容易得分的一句话。**

### ⑥ 断网自证

- **触发信号**：评委问"你们真的没有调外部 API 吗" / "现场断网怎么办"。
- **4 号动作**：打开浏览器 DevTools 的 Network 面板（提前清空），拔网线/关 Wi-Fi，重跑一次任务（用 MockEngine 或已跑通的本地引擎）。
- **观众看到什么**：Network 面板里**只有 127.0.0.1 / localhost 的请求**，系统照样跑完、大屏照样在动。**这一条是产品经理说的"断网从应急变成卖点"的现场版。**

### ⑦ 现场随机指定参数

- **触发信号**：评委说"你换个参数我看看" / "换一组规则"。
- **4 号动作**：在任务配置页改 `target_url` 的路径/参数位（靶场内已授权的点位），重跑；同时把大屏切到新任务。若引擎不可用，切 `ENGINE_MODE=mock` 并**当场声明**"当前为契约桩回放，非实时推理"。
- **观众看到什么**：一个新的轮次序列、一个新的第 1 轮（不是复读上一遍）、`prev_round_id` 从 `NULL` 重新开始。**能现场跑新输入，是"不是硬编码"最直接的回答。**

### ⑧ 后端/DB 挂了

- **触发信号**：大屏白屏 / 接口全 500 / MySQL 连不上。
- **4 号动作**：跑 `scripts/health.sh`（一键检查 MySQL/后端/前端/引擎四段），按提示重启缺失组件（提前彩排过）；若 60 秒内无法恢复，切到**预录的逐轮日志回放页**（一个纯静态 HTML，读本地 JSON 播放），并声明"非实时"。
- **观众看到什么**：60 秒内画面重新有内容。**任何一个"现场死机超过两分钟"的场景，都会盖掉前面所有技术亮点。**

## 第十章 常见坑清单（12 条，都是这类项目真会踩的）

| # | 症状 | 原因 | 解法 |
|---|---|---|---|
| **1** | 大屏"不实时"：点开始后 30 秒才一次性刷出 20 条事件 | **反向代理/框架缓冲 SSE**。Nginx `proxy_buffering on` 会攒包；gzip 也会攒 | 响应头加 `X-Accel-Buffering: no` + `Cache-Control: no-cache`；Nginx 配 `proxy_buffering off; proxy_read_timeout 3600s; gzip off;`；**开发期 Vite `server.proxy` 也要关缓冲** |
| **2** | `MySQL server has gone away` / 插入长文本被截断 | 单轮请求+响应全量入库，撞 `max_allowed_packet`，或 `TEXT` 上限（64KB）撑爆 | **根本不存全文**（见 4.4）；摘要字段用 `VARCHAR(2048)` 显式截断；`raw_output` 用 `MEDIUMTEXT`；`max_allowed_packet` 调到 16M 兜底 |
| **3** | PDF 里中文全是方块 / 乱码 | 无头浏览器或字体库没带中文字体；CI/镜像里没字体 | 把开源中文字体**打进部署包**并在 CSS `font-family` 显式声明（含 fallback 链）；导出后用 `pdftotext` 抽一段中文自检；**部署包里加一个自检脚本** |
| **4** | 证据链时间线错乱：第 2 轮的时间早于第 1 轮 | DB 存本地时间、应用存 UTC、日志又用另一个时区；`DATETIME` 无时区语义 | **全链路统一 UTC 存储**（`DATETIME(3)` + 应用层统一 `utcnow()`）；前端统一 `fmtLocal()`；`server_time` 放响应包壳里做校对；**同一个事件只取一次时间戳，透传下去，不要各层各取一次** |
| **5** | 同一任务出现两条"第 3 轮"，证据链废了 | 幂等键用了随机 uuid 或时间戳；或重试时重新生成 `round_id` | 幂等键**必须是 `(task_id, round_no)` 唯一键**；`round_id` 由 4 号生成并透传；`INSERT ... ON DUPLICATE KEY UPDATE round_id=round_id`；重试复用同一个 `round_no` |
| **6** | 开三个页面后 DB CPU 拉满 | 每个页面都在 1s 轮询 `GET /rounds`（全量、无分页） | 大屏走 SSE，**轮询只作降级且只查 `GET /tasks/{id}` 轻状态**；`GET /rounds` 强制分页 + `from_round` 增量；前端加"页面隐藏时暂停轮询"（`visibilitychange`） |
| **7** | 一个客户端订阅 SSE 后，全站接口变慢 | SSE 端点里写了同步 DB 查询，**阻塞事件循环** | SSE 生成器内只读内存队列；DB 查询走 `asyncio.to_thread` 或 async 驱动；**别在 SSE 循环里做重查询** |
| **8** | SSE 端点 401，怎么都带不上 token | **`EventSource` 不支持自定义 Header**，`Authorization` 发不出去 | 用 **Cookie**（同源自动带）或 **query 参数 token**；或者干脆让 SSE 端点只校验 `task_id` 归属 + 同源 `Origin` |
| **9** | 前端某轮显示空白/白屏 | 后端返回了新的枚举值，前端 `switch` 无 default | 所有枚举渲染走 `renderEnum()`，未知值输出灰色"未知: XXX"；**加一条前端单测：喂一个 `"FOO_BAR"` 不崩** |
| **10** | 报告里的轮次数与页面上的不一致 | 报告读了 `round` 表，但页面读的是内存状态；或导出时任务还在跑 | 导出**强制校验 `status ∈ {TERMINATED, REPORTED}`**；报告只读 DB；**运行中导出返回 409** 并提示"任务未终止" |
| **11** | 演示机上 MySQL/Ollama/后端 端口冲突，起不来 | 硬编码端口 3306/11434/8000，现场被占 | 全走 `.env` 配置（附录 B）；`scripts/dev_up.sh` 启动前**先做端口占用检查并打印明确错误**；准备 `PORT_OFFSET` 一键偏移 |
| **12** | 时间"看起来对"但 `cost_ms` 与 `ended-started` 差很多 | 一个用应用时钟、一个用 DB 时钟；或漏算模型队列等待 | **`cost_ms` 只由引擎上报**，4 号不算；如需自算，用同一时钟源；大屏显示 `cost_ms` 时标注"引擎耗时" |

**追加两条工程卫生（不算坑，但踩了很浪费时间）**：

- **`utf8mb4` 不是可选项**。MySQL 的 `utf8` 实际是 `utf8mb3`，遇到四字节字符直接报错或截断。建库建表必须显式 `CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci`。
- **`DATETIME` vs `TIMESTAMP`**：`TIMESTAMP` 会自动做时区转换且范围到 2038。证据链要稳定，**统一用 `DATETIME(3)` + 应用层存 UTC**。

## 第十一章 只做三件事

如果这周只有三件事的时间，做这三件（按顺序，前面不做完不许开后面）：

### 第一件：**契约冻结 + MockEngine**（1~1.5 天）

产出：`api-contract.md` v1.0 + 三套剧本的假引擎 + 一个环境变量开关。

**为什么是第一件**：它是你**唯一一件"做完之后所有其他事加速"的工作**。不做它，你后面每一件事都在等；做了它，你的六项 P0 里五项立刻解耦。而且它是**契约桩能当答辩兜底**的前提——现场引擎崩了，你还有一个能跑的系统。

### 第二件：**`round` 表 + `GET /rounds` + 证据链 JSON 导出**（1.5 天）

产出：8 张表 + 分页查询 + 一份能让外人读懂的证据链 JSON。

**为什么是第二件**：架构师判定这是**"怎么证明不是硬编码"的唯一解**，也就是答辩命门。它还有个隐性好处——**它逼你把所有字段的真实语义想清楚**，反过来验证契约定得对不对。你会发现"哦 `rejected_reason` 原来是必须的"这类问题，早发现比联调时发现好一百倍。

### 第三件：**SSE + 大屏**（1.5 天）

产出：`GET /tasks/{id}/events` + 一页大屏，显示轮次/策略/拦截标记/决策摘要/降级角标。

**为什么是第三件**：它是评委**唯一能直观看到"AI 在干活"的窗口**。技术上它不难，但它决定答辩的第一印象。而且它同时验证了前三件事是否真的串起来了——**大屏亮得起来，说明闭环的数据链路是通的**。

---

**如果只有一天**：做大屏 + MockEngine。用一个能动的画面撑住整场答辩，比十页写得很漂亮的表结构有用。

**如果还剩半天**：写这份 `GET /rounds` 的接口自测用例，然后找 2 号来，让他照着 JSON 回答那五个问题。**他答不出来的地方，就是你答辩会被问倒的地方。**
