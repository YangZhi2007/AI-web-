# 25 · 无训练 RAG 幻觉修复落地说明（v0.30）

## 一、背景与决策

用户新需求：**"可以不训练 AI 吗？目前没有条件训练，有没有办法用模拟数据或更好的办法？"** 经 find-skills 扫描（本地 12 个技能 + 远程市场）确认没有专门的"无训练幻觉修复"技能——这是架构决策，不是装技能能解决的。用户确认：**目标两者都要**（前端完整演示 + 可插拔真实推理），**有 Ollama 但无训练条件**。

## 二、核心判断：训练不是这条主线的必要条件

HallucinationFix V1.1 的主线是"**模型只负责回答，判定由独立真值库完成**"。七环节里：

| 环节 | 是否需 GPU 训练 |
| --- | --- |
| 题目加载 / 批量推理 / 幻觉判定 / 成因归因 / 数据集构建 / 对比评测 | 否（确定性计算或推理） |
| 第 6 环 LoRA 微调 | 是（唯一卡点） |

V1.1 自己都砍掉了裁判模型（8GB 装不下两个 7B）、把提示词缺陷类样本剔除了——它承认不是所有幻觉都能靠训练解决。所以问题本质是"去掉训练后拿什么实现修复与前后对比"，答案是用 **RAG 真值证据注入** 替代 LoRA：同一模型在无证据 / 有证据两种条件下作答，在验证集上真实计算幻觉率下降。

## 三、三条路线对比与选择

| 路线 | 特点 | 选择 |
| --- | --- | --- |
| RAG 检索增强 | 真值库当检索源、证据注入提示词、零训练、效果真实可测 | **采用**（主线） |
| 提示词 + 规则约束 | 见效快、零训练，对深层知识盲区不如 RAG | 融入归因分类 |
| 纯前端 Mock 演示 | 契约桩 + 预置指标，答辩够用 | **采用**（默认模式） |

最终方案：**前端完整可交互演示 + 可插拔本地 Ollama 推理接口**，全程零训练。

## 四、实现

### 引擎 `webapp/js/hf.js`（独立 `window.HF`，不碰绕过系统 `window.Probe`）

- **真值库**：训练池 12（T-xx）+ 验证池 10（V-xx），编号空间独立、交集为空，启动自检。每题含场景、题面、标准结论、结论锚点 key、关键事实点、base/rag 两种典型输出。
- **判定层（确定性、零模型）**：结论锚点命中（必要条件）+ 事实点覆盖率 ≥ 0.6（V1.1 M-05 严格组合判定）。用结论锚点而非结论全称逐字匹配，避免把换说法的正确答案误判为幻觉。
- **归因层（规则化）**：四类成因按规则次序匹配（上下文偏差 → 提示词缺陷 → 推理逻辑缺陷 → 知识盲区），理由带原文片段，无套话（V1.1 M-12）。
- **修复层（替代训练）**：`buildEvidence()` 把标准结论与关键事实转成证据条目，`makePrompt()` 在推理时注入。模型权重零改动。
- **推理双模式**：`mock`（默认，预置输出，零外部请求）/ `ollama`（用户显式切换并填地址后调用本地推理，绝不训练）。
- **评测层**：同一池上跑 base / RAG 两版本，用同一判定算法真实计算幻觉率、下降 pp、修复样本数、四类分组。
- **Store**：`hf.eval` 键独立于绕过系统 Store，跨页共享评测结果。

### 页面（4 个子页 + 总览改造）

- `hf.html` 总览：从"导航壳"升级为真实入口，4 个已上线页为链接、4 个规划页禁用，NO TRAINING 声明。
- `hf_probe.html` 探测面板：池选择 + Mock/Ollama 模式切换 + 运行 + 逐题双版本判定表。
- `hf_sample.html` 样本溯源：幻觉样本 + base/rag 原文对照 + 真值证据 + 规则归因（可展开）。
- `hf_truth.html` 真值库：双池自检读数 + 12/10 行题目表。
- `hf_eval.html` 评测对比：四格读数 + 四类分组柱状图 + 无训练口径说明。
- `css/hf-app.css` / `js/hf-app.js`：幻觉功能区独有样式与编排层。

## 五、诚实口径（关键）

验证池 10 题的评测结果（真实确定性判定算出）：

| 场景 | 题数 | base 幻觉率 | RAG 幻觉率 |
| --- | --- | --- | --- |
| 知识盲区 | 4 | 100% | **0%** |
| 推理逻辑缺陷 | 3 | 100% | 100% |
| 提示词缺陷 | 1 | 100% | 100% |
| 上下文偏差 | 2 | 100% | 100% |
| **整体** | **10** | **100%** | **60%（下降 40pp，修复 4 题）** |

**这个结果刻意保持诚实**：RAG 只治知识盲区，对推理逻辑 / 提示词 / 上下文三类无效（保持 100%）。这恰恰印证了文档四类归因存在的意义——不同成因需要不同手段，不是所有幻觉都能靠一种办法抹平。mock 模式的输出是契约桩预置，但**判定与下降计算是真实算法**；切到 Ollama 后 base/rag 由真实推理产生，仍不训练。

## 七、过程中修的真 bug

1. **判定口径缺陷**：初版用"结论全称逐字匹配"，自然语言输出换说法就误判，RAG 修复率只有 10%。改为结论锚点 key + 事实覆盖率后修复率合理。
2. **表格 DOM 结构**：`renderProbe` / `bootTruth` 把 `<td>` 直接挂到 `<tbody>` 而没有 `<tr>`；浏览器会自动补 tr 但验收选择器数不到、DOM 不规范。改为先 `tr.appendChild(td)` 再 `tbody.appendChild(tr)`。
3. **验收器过时断言**：qa-v027 原断言"8 入口全禁用"，新结构是 4 链接 + 4 禁用，更新为正确的结构契约（并限定选择器到 `#hfGrid .hf-page`，避开二级导航同属性干扰）。
