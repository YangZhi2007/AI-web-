## 3. 接口测试（curl / 自动化）

**结论：本项目为纯前端静态站点，无后端接口服务，本项 N/A。** `HttpEngine.analyze` 为占位实现，主动 `reject` 并提示「真引擎未接入，不发起任何外部请求」——符合「零外部请求」设计约束。

- 断言：事件顺序、字段枚举（`response_class=BLOCKED|ANOMALY|NORMAL|TIMEOUT`）、`mock_flag` 仅真引擎为 `false`

## 8. 重构后复审（文件外置 + L1-L3 优化）

> 执行于 2026-11-09（GMT+8）。目标：将内联 HTML/CSS/JS 分层外置，并对上一轮发现的 L1-L3 低危项做优化，随后复跑全套审查。

### 8.1 文件分层外置

| 原结构 | 新结构 |
|---|---|
| `index.html`（1640 行，内联 `<style>` + 2 段 `<script>`） | `index.html`（236 行 HTML 壳）+ `css/index.css`（1177 行）+ `js/index.js`（170 行） |
| `console.html`（1133 行，内联 `<style>` + 2 段 `<script>`） | `console.html`（231 行 HTML 壳）+ `css/console.css`（334 行）+ `js/console.js`（531 行） |
| 两页各含一份"过渡+涟漪"脚本（重复） | 收敛为共享 `js/core.js`（57 行），两页 `<script src="js/core.js" defer>` 共用 |

- 设计 token（`:root`）与页面级样式**各自保留在 `css/{page}.css`**：两页 token 命名存在历史差异（`--bg-2/--surface/--line-2` vs `--bg2/--panel/--line2`），强制合并为单一共享 token 有破坏风险，故保持页面自治、仅去重过渡/涟漪逻辑到 `core.js`。
- head 防闪烁脚本（读 `sessionStorage('pt-nav')` 加 `pt-cover`）因须在首帧前同步执行，**保留为 `<head>` 内联**，不外置。
- 外置脚本统一 `defer`；保持与原"body 末尾内联"等价的执行时序（DOM 解析后、文档顺序执行）。

### 8.2 L1-L3 优化（均落在 `js/console.js`）

| 编号 | 优化 | 落地方式 | 影响 |
|---|---|---|---|
| L1 | `displayUrl` 非法 URL 兜底 | catch 分支由 `return String(url)` 改为 `return '(invalid)'`（纵深防御；调用方仍经 `esc` 转义） | 极低 → 已消除 |
| L2 | `CONFIG` 冻结 + 运行期选择拆出 | `CONFIG` 改为 `Object.freeze(...)`（ENGINE_MODE / API_BASE_URL / TICK_SPEED / MAX_ROUNDS 全程只读，是真正需防误改的常量）；将**运行期可切换的剧本选择**从 `CONFIG.MOCK_SCRIPT` 拆为独立可变对象 `RUNTIME.script`（UI 下拉与 `?script=` 参数写入，测试亦可切换） | 低 → 已消除，且保留运行期可变性 |
| L3 | `genId` 使用密码学随机 | `Math.random()` 改为 `globalThis.crypto?.randomUUID()`（带 `Math.random` 降级，兼容 `file://` 非安全上下文） | 低 → 已消除 |

> L2 实施中曾一度误将 `MOCK_SCRIPT` 拆为顶层 `let` 基本类型，导致"对它的赋值无法被 MockEngine 观测"（按值捕获）。复审复跑即暴露该回归，遂改为可变对象 `RUNTIME.script`（对象属性才能被共享观测），既满足冻结常量、又不破坏运行期切换。此回归已被测试兜住。

### 8.3 复审结果

- **冒烟 / 语法**：`js/core.js` `js/index.js` `js/console.js` 经 `node --check` 全部通过；HTML 已无内联 `<style>` 与多余 `<script>`（仅留 head 防闪烁内联）。
- **加载冒烟**（最小 DOM mock + `vm` 沙箱）：`core.js` 与 `index.js` 顶层执行均**无异常**；`console.js` 由 64 项单测在加载期即执行初始化，亦无异常。
- **单元测试**：`docs/scripts/code-review-run-tests.js` 改为加载外部 `webapp/js/console.js`，**64/64 通过**（含 L1 兜底改为 `'(invalid)'`、L2 经 `RUNTIME.script` 切换三剧本、L3 不依赖 `genId` 格式）。
- **结论**：外置与 L1-L3 优化后，行为等价、零回归；可维护性显著提升，且无新增高危/中危项。

### 8.4 冗余区块优化（跨页重复的过渡/涟漪 CSS）

- **问题**：`js/core.js`（共享的跨页圆形揭幕过渡 + 按钮涟漪逻辑）已抽成单份，但其对应的样式（`.pt` / `.pt__mark` / `.pt__dot` / `.ripple` + `@keyframes ripple`）却仍**各在 `index.css` 与 `console.css` 各写一份**，属跨页重复副本（约 50 行 × 2）。
- **处理**：新建 `webapp/css/core.css`（94 行），收拢两页完全一致的过渡/涟漪样式；从 `index.css`（−70 行）与 `console.css`（−11 行）中删除该副本；两页 `<head>` 新增 `<link rel="stylesheet" href="css/core.css">`（置于页面专属 CSS 之前，确保首帧前可用）。
  - 页面专属样式（`.btn-back` 返回按钮、`@keyframes dotFlash/ping` 等页面本地动画）**保留在各自 css 文件**，不强行合并——各页独立加载自身样式表，跨文件同名 keyframes 不构成冲突。
- **验证**：`index.css` / `console.css` 已无独立的 `.pt` / `.ripple` / `[data-ripple]` 定义；`@keyframes ripple` 全局唯一（仅 `core.css`）；三份 CSS 大括号配平；复跑单元测试 **64/64 通过**，无回归。
