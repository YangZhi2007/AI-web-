# 管理员登录与看板访问控制（v0.34）

## 1. 需求与落地范围

需求是「后端需要增加管理员登录页」。落到本项目（`webapp/hf/` 独立后端看板、file:// 纯前端演示）意味着两件事：

1. 有独立的**管理员登录页**，而不是弹窗或行内表单；
2. 登录后才能真正进入看板——即**访问控制**，否则登录页只是摆设。

本次交付包含这两层：`login.html` + `js/auth.js`（认证模块）+ 9 个看板页的访问守卫 + 侧栏账户条（当前管理员 / 退出）。

## 2. 认证机制

| 环节 | 实现 |
|---|---|
| 口令存储 | 不存明文。`salt` + `SHA-256(salt:口令)`，再以 `SHA256(h‖salt)` 迭代 **2048 轮**，只保存 64 位十六进制派生值 |
| 口令校验 | 前端重新派生并与存储值比对；账号不存在时也走一次派生（decoy salt），避免用响应时间探测账号是否存在 |
| 会话 | `sessionStorage`（关闭标签页即失效），含 `user / role / scope / at / exp`，上限 **8 小时**；读取时校验 `exp`，缺失或过期即视为无效并清除 |
| 失败限制 | 连续失败 5 次起锁定，锁定时长 `15s × 2^n` 递增；锁定期间即使口令正确也拒绝 |
| 回跳 | `?next=` 只接受本目录 9 个页面的文件名，拒绝协议、斜杠、`..`，非法一律回落 `index.html` |
| 防内容闪现 | 守卫在 `head` 内同步执行，跳转前先把文档设为 `visibility:hidden` |

SHA-256 为纯 JS 实现（自带在 `auth.js`），不依赖 `crypto.subtle`——后者在非安全上下文可能不可用。该实现已与 Node 原生 `crypto` 在 5 组用例（空串、ASCII、长串、UTF-8 中文）上逐字节比对一致。

**演示凭据**：账号 `admin`，口令 `HfLab@2026`（写在登录页说明区，便于评审直接进入）。

## 3. 安全边界（必须如实理解）

这是全篇最重要的一节：

> 本站点是 **file:// 纯前端演示，没有服务端**。任何客户端校验都能被绕过——清掉 `sessionStorage`、改 `auth.js`、用开发者工具直接写会话，都能进入看板。

因此本次交付的是**访问控制流程与界面**，不是真实身份认证。它带来的实际收益是：流程完整、口令不落明文、有会话有效期与失败锁定、能防止顺手误入；它**不能**防住有意攻击者。

登录页说明区、`auth.js` 文件头、本文件三处都已写明这一点，避免被误读为「系统已具备认证安全性」。

### 接入真实后端的迁移路径

若后续接服务端，改造点集中且明确：

1. `POST /api/login` 由服务端校验口令（Argon2id/bcrypt），成功后下发 **HttpOnly + Secure + SameSite** Cookie，前端不再持有任何凭据；
2. 删除 `auth.js` 中的 `ACCOUNTS`、`derive()`、`sha256()`；`login()` 改为一次 `fetch`；
3. `session()` 改为 `GET /api/session`（或在页面渲染前由服务端注入用户信息）；
4. **权限校验必须在服务端做**——每个数据接口都要独立鉴权，不能因为前端隐藏了页面就认为安全；
5. `guard()` 保留但语义变为「未登录跳登录页」的体验优化，不再是安全边界。

## 6. 回退

本次为新增为主，回退粒度清晰：

- 撤销访问控制、保留页面：从 9 页删除 `js/auth.js` 与 `HFAuth.guard()` 两行，删除侧栏 `.hf-acct` 块与 `bindAccount()`；`login.html` 可保留或删除。
- 整体回退：`git revert <v0.34 commit>`，或检出 `v0.33.0` tag。

注意：`qa-v027/v030/v032` 已加入登录前置，若撤销守卫需一并撤掉它们的 `hfLogin()` 调用，否则会因找不到登录表单而失败。
