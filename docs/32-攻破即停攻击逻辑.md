# 32 · 攻破即停：从固定轮数剧本改为状态驱动攻击

版本：`v0.36.0` / `v0.36.1` / `v0.36.2`　日期：2026-11-19　范围：`webapp/` 功能页（后端看板 `webapp/hf/` 零改动）

## 1. 问题与根因

测试中发现「每次点击攻击都是固定次数」。定位到两条路径都在回放剧本：

1. `AttackAgent.analyze()` 用 `for (no=1; no<=CONFIG.MAX_ROUNDS; no++)` 驱动，8 是硬停机条件。
2. `planNextRound()` 按「没试过的算子优先」固定顺序推进，`AGENT_PROFILES` 又把 `breakAt` 写死成某个算子编号。同一个网址每次都在同一轮撞上同一个算子，因此轮数恒定。
3. URL 输入框按回车调用 `runTask()` 时不带 `agent` 标记，会落到 `AnalysisEngine` 的三剧本固定轮次；与点击按钮的行为不一致。

结论：当时的「自主攻击」只是确定性剧本回放，不是"打到攻破才停"。

## 2. 新终止语义

| 项 | 旧 | 新 |
|---|---|---|
| 正常停机 | 跑满 8 轮 / 撞上固定 `breakAt` | 只有独立裁决 `CONFIRMED`（标注点位真被触发） |
| `MAX_ROUNDS=8` | 攻击预算、终止条件 | 仪表刻度容量；`AGENT_CAP=8` 仅作异常看门狗 |
| 收敛轮 | 画像里写死的算子编号 | 由「网址 + 任务 ID」派生的种子决定，落在画像区间内 |
| 未攻破 | HARD 固定 8 轮打不穿，输出"未攻破"报告 | 三种画像都打到攻破；未攻破只由越界/取消/看门狗产生 |
| 看门狗触发 | — | `terminate_reason='GUARD'` → 状态 `error`，不输出漏洞结论 |

`resolveTerminalState()` 优先级：`OOS → MAX_ROUNDS（旧契约桩兼容）→ GUARD → HIT+降级轮 → HIT → error`。

## 3. 种子与可复现

- `seedOf(url + '|' + taskId)` 生成 32 位 FNV-1a 种子，`rngOf(seed)` 给出确定性随机数。
- `agentPlanOf(profile, rng)` 把静态画像实例化：`breakRound = base + floor(rng()*jitter)`，并 clamp 到护栏容量。
  - 标准靶场 `base=3, jitter=3` → 3–5 轮；
  - 加固靶场 `base=6, jitter=3` → 6–8 轮；
  - 诱导靶场 `base=5, jitter=3` → 5–7 轮，降级从收敛前 2 轮开始，收敛前 1 轮出现一次误报。
- 种子与收敛轮写入报告封面「收敛种子 / SEED」，同一任务可用 `agentPlanOf()` 复算该轮；同一网址再次攻击因任务 ID 不同，轮数不再必然相同。
- 诱导靶场的误报仍由 `oracleVerdict()` 判为 `REFUTED`，智能体不提前收工，`analyzeBreach()` 把它作为反证列入漏洞分析。

## 4. 联动改动

- `runTask()` 默认走 `AttackAgent`；仅显式 `agent:false` 保留三剧本契约桩。`#startBtn` 点击与 `#urlInput` 回车共用 `submit()`，都会写 `pendingRun` 并翻到监控页，不再出现"回车在本地偷偷跑一份"。
- 报告：「轮次预算」改「攻击轮次」，小字从"未使用 N 轮预算"改为"攻破即停 · 未继续投递"，新增收敛种子事实格；看门狗语义写入执行摘要与闭环说明。
- 配置页画像预览复用 `agentPlanOf + planNextRound + agentResponse`，展示"示例 N 轮攻破"，不再预告"未攻破"。
- 文案：`console.html`、`monitor.html`、`settings.html`、`about.html`、`report.html` 同步去掉"固定轮数/预算终止/打不穿"口径；`app.js` 的 `aria-label` 同步。
- unslop：保留现有 SOC 卷宗皮肤、酸柠单强调、8 格刻度与双轨裁决 signature；只改因终止语义失实的文案，不新增视觉装饰。

## 5. 验证

新增 `docs/scripts/qa-v036-until-breach-accept.js`，28/28 通过。关键结论：

- 三种画像都 `breached=true`、`stopReason=BREACH`、终态与种子收敛轮一致；
- 同一网址连续 8 次攻击，实际轮数分布 `3/4/5`，不再固定；
- 诱导靶场 1 次 `REFUTED`，反证进入分析，攻破轮在误报之后；

- 零外部请求、零运行时异常。

## 6. v0.36.2 界面口径修复：不再出现"8 次"

攻击逻辑虽已改成攻破即停，监控页仍沿用"轮次预算"的视觉语言：`0 / 8` 分母、8 个预置空槽、`轮次进度 %`、`护栏 8 · 非攻击预算`。用户看到 8 仍会理解为固定攻击 8 次。本次把四处同源展示统一改为"实际投递流水"：

| 位置 | 旧 | 新 |
|---|---|---|
| 监控页主读数 | 当前轮次 `0 / 8` | 已投递轮次 `0 轮 · 攻破即停`，无分母 |
| 监控页刻度 | 预置 8 格 + 当前格虚线 | 只列实际投递轮次，投递到第几轮显示几格；无空槽、无 cur 占位 |
| 监控页脚注 | 轮次进度 X% ／ 护栏 8 | 已投递 N 轮 · 攻破即停 ／ 无攻击次数上限 |
| 报告页 02 | `N / 8` + 8 格含空槽 | `N 轮 · 攻破即停` + 仅实际轮次流水 |
| 报告页卷首/附录 C | `N / 8`、`轮次上限 / MAX 8` | `N 轮`、`停机规则 / STOP = 攻破即停` |
| 配置页概览/画像卡 | `Max rounds 8`、`示例 N 轮 / 护栏 8` | `停机规则 = 攻破即停`、`示例 N 轮攻破即停`；刻度不补空槽 |

态势 SVG 的 8 个方形节点是攻击链拓扑位，不显示数字、只按实际轮次点亮，保留。

`qa-v036` 增补 3 条界面断言（31/31）：主读数无 `/ 8` 分母、脚注无护栏数字与进度百分比、刻度格数等于实际投递轮次且无预置空槽。回归全绿：单测 99/99、e2e 62/62、v021 22/22、v022 51/51、v023 45/45、v024 36/36、v025 23/23、v026 31/31、v027 13/13、v030 20/20、v032 20/20、v034 32/32、v035 36/36。

## 7. 边界与口径

- 这是 `file://` 零外联演示，所有"攻击"都是本地 mock 响应，不向目标地址发请求。
- 攻破轮由种子派生，属于演示收敛模型，不是真实漏洞发现能力的证据。
- 越界目标仍按合规边界只跑 3 轮纯模拟并标 `OOS`，不适用"直到攻破"。
