# 16 · 差异化改造：双通道裁决闭环（2026-11-15）

> 触发：组长反馈「项目没特色，功能与市面 AI 自动挖洞很像，核心就是 AI 根据 WAF 拦截回显生成不同攻击脚本去测试，还有测试次数限制，容易被评委问区别」。
> 关系：本文是 **`docs/00` §2.4 正式口径的技术细化**，不改赛道、不重写用词替换表；是 `docs/15` §5 里「声称 → 确认 → 证伪计数视图」从「未做」推进到「演示机制已跑通」的落地记录。
> 版本基线：`v0.22.0`。

---

## 0. 可直接回复组长的结论

> 组长的判断是对的，而且问题比「撞车」更具体：**旧版代码里 AI 说命中就是命中，系统里根本没有第二条独立判定通道**，所以「可信度验证」只是讲法，不是机制，评委一追就穿。
> 优化不是换个说法，而是补上这条通道：把「WAF 没拦住 / 响应异常」和「漏洞点位真的被触发」拆成两件事，用实验前的点位标注做独立裁决，模型结论降级为「声称」，冲突轮次如实标成证伪并计入报告。
> 于是差别变成一句话：**别家优化的是绕过成功率，我们优化的是结论可信度**——能给出「AI 声称 1 条、验证器确认 0 条、证伪 1 条、待复核 3 轮、信息增益出现在 R04」这种别家给不出的表。
> 「8 次」不再是拍脑袋的次数限制，而是**固定预算的实验控制变量**：配置页标为冻结常量只读投影，报告页画成 8 格预算刻度，并标出信息增益出现在第几轮；真实系统的终止条件应由验证器置信度决定。
> 边界照旧说清楚：当前是**演示标注集**，不是真实靶场，不构成实测误报率，讲稿里仍要说「未做真实 oracle 与误报率量化实验」。

## 1. 根因：为什么「没特色」不是文案问题

逐条翻旧版（`v0.21.0` 及之前）代码，四个具体事实：

| # | 代码事实 | 后果 |
|---|---|---|
| 1 | `MockEngine.analyze()` 每轮硬编码 `validation_result:'PASSED'` | 模型原文里的 `validation:PASSED` 是**模型自证**，却被当成「已校验」，没有任何第三方复核 |
| 2 | `verdict` 直接由 `s.hit` 决定，`confidence:0.91` 写死，`findings[0]` 直接取 `hit_signal` | AI 说命中 = 系统结论，AI 说没有 = 未检出，**没有独立判据** |
| 3 | `docs/00` §6.9 把「双重判定（规则 + AI 语义）+ 误报量化」列为 **P1 待做**，§3 标注「无量化即为口号」 | 「降低误判」在正式口径里本来就还不能当结论讲，功能页也没有支撑它的界面 |
| 4 | `CONFIG.MAX_ROUNDS = 8` 是 `Object.freeze` 的编译期常量，终止只看 `hasHit` 或 `length>=MAX_ROUNDS` | 8 次既不是收敛判据也不是实验设计，评委问「凭什么 8 次」时只能答「演示预算」 |

所以只要功能被描述成「AI 看 WAF 回显 → 换脚本 → 再试、最多 8 次」，它**确实**和市面的 AI 自动挖洞 / 自适应 payload 生成同质。上一轮（`docs/15`）给出的「改讲法 + 把失败样本当主证据」只能缓解，不能消除这个同构。

## 2. 改造后的定位（不改赛道，只补机制）

> 面向授权目标、在 WAF 环境下对**已知漏洞类型**做自适应探测；
> **不把 AI 的判定当结论**，把每条结论降级为「声称」，交给与模型输出解耦的独立裁决复核；
> 输出物是可核对的可信度证据（声称 / 裁决 / 分歧轮 / 逐轮证据链），而不是绕过成功率。

这条与 `docs/00` §2.4 正式口径一字不冲突：正式版说的是「提升检出能力并降低误判」，本轮说的是**用什么机制让「降低误判」变得可核对**。答辩口语版仍可用「AI 不挖洞，AI 学绕」，补一句「但绕过不等于漏洞成立，所以我们另设一把尺」。

**核心 idea：绕过 WAF ≠ 漏洞成立。** 安全领域的常识是「WAF 没拦住」只说明规则没匹配上，不等于靶场点位真的发生了可复现的状态变化。市面工具普遍把前者当成功，本项目把两者分开，误报因此从「要藏的缺陷」变成「系统能定位到第几轮、并能给出理由的研究对象」。

## 3. 与市面 AI 自动挖洞的逐项区别（答辩主表）

| 维度 | AI 自动挖洞 / 自适应 payload 工具 / 传统扫描器 | 本项目（v0.22） |
|---|---|---|
| 优化目标 | 绕过成功率、发现数量、覆盖 CVE | 每条结论的**可信度与可核对性** |
| 判定依据 | 响应码 / 回显差异 / 模型自证 / 固定规则匹配 | 实验前点位标注（ground truth）+ 独立裁决；**不读取** `verdict` 字符串、`confidence`、模型原文的自证 |
| 成功定义 | 绕过 WAF 或命中特征即算成功 | 必须标注点位触发且被裁决 `CONFIRMED` 才算确认 |
| 失败处理 | 未命中即结束，失败样本通常不进交付物 | 未收敛 / 模型降级 / 越界 / 证伪四类**全部进报告**；越界明确声明不构成真实结论 |
| 输出物 | 漏洞列表 / PoC | 声称-裁决双轨对照、证伪与待复核计数、逐轮 `round_id`/`prev_round_id`/模型决策原文、5 附录可打印报告 |
| 「测 8 次」 | 超参或暴力枚举上限 | **固定预算的实验控制变量**：配置页冻结只读投影、报告页 8 格预算刻度、信息增益轮标注；真实系统按验证器置信度提前终止 |
| 误报 | 靠人工复核或规则门控兜底 | 视为研究对象：能定位到具体轮次、给出「仅绕过规则，点位未出现状态变化」的证伪理由 |

> 讲这张表时的禁忌：**不要说「我们降低了误报率」**。§8 列了仍未做的实验；只能说「我们把误报变成可定位、可计数、可复核的对象」。

## 4. 「测试次数限制」怎么重新讲（组长点名的第二个软肋）

三句话，逐层收窄：

1. **8 是预算，不是判据。** `MAX_ROUNDS` 是 `Object.freeze` 常量，配置中心 02 把它标成「冻结常量只读投影」，页面不提供写入，避免把演示参数说成引擎能力；真实系统的终止条件应由验证器置信度决定。
2. **预算是实验控制变量，不是玄学数字。** 配置页剧本库展示每套剧本「会用几轮」，报告页 02 展示「这次实际花了几轮」，两页共用同一把 8 格刻度；`NO_CONVERGE` 跑满 8 轮仍如实记未检出、不刷成成功，正好证明预算耗尽不等于收敛。
3. **能指出预算花在哪一轮。** `credibility.signalRounds` 标出信息增益轮（确认 / 证伪 / 漏报出现的轮号）：`CONVERGE_3` 是 R03，`DEGRADED` 是 R04，`NO_CONVERGE` 为空。评委再问「为什么不全跑 8 次」，答的是「早停由裁决信号触发，固定预算只保证每次演示可复现」。

## 5. 本轮实际落地了什么

### 5.1 引擎层（`webapp/js/console.js`）
- 新增 `GROUND_TRUTH`（`LAB-GT-01`）演示标注集：实验前标注每轮算子是否在靶场点位产生可复现状态变化，**运行时只读、不参与策略选择与模型判定**。
- 新增 `oracleVerdict(aiClaim, gt, ctx)`：优先级 `NOT_APPLICABLE`（越界）→ `CONFIRMED`（点位触发且声称阳性）→ `REFUTED`（点位未触发但声称阳性）→ `MISSED` → `UNCONFIRMED`（降级证据不足）→ `TRUE_NEGATIVE`。**REFUTED 优先于 UNCONFIRMED**，标注已明确未触发就不能用「降级」把误报含糊过去。
- 新增 `buildCredibility(report)`：聚合并只计数（`claims / confirmed / refuted / missed / unconfirmed / disagreement / signalRounds / cap / used`），不外推误报率；旧会话缓存缺 `credibility` 时按同一规则现算。
- 每轮新增 7 个字段：`ai_claim / gt_ref / gt_note / gt_triggered / oracle_verdict / oracle_cn / oracle_source`（T01 冻结契约「只增字段、不改语义」，已同步写入 `webapp/js/api.js` 契约注释）。
- 模型决策原文里的 `validation:PASSED` **原样保留**，但明确标注为模型自证、不作为裁决依据——这个对照本身就是答辩素材。

### 5.2 界面层（unslop：安静 chrome + 一个记忆点）
- **证据链页**新增「独立裁决双轨」卡：上轨 `AI 声称`、下轨 `独立裁决`，各 8 格；横杠 / 实心 / 叉 / 虚线框 / 菱形 / 斜杠六类形状 + 中文短标签三重编码，待复核格用 2px 框与一条向上错位刻痕标出。下方 4 个读数与「待复核轮次逐轮核对」明细表，列出模型声称、点位标注、裁决与标注说明。
- **结论优先级**：结果卡新增「独立裁决优先」条，明确「模型侧判定仅作记录，出现分歧时不作为最终判定」，消除「已检出 / 置信度 0.91」与「确认 0 / 证伪 1」的表面矛盾；报告页 02 同步写明「卷首是任务终态（引擎状态机），不是独立裁决结论，冲突时以裁决为准」。
- **报告页 02** 新增裁决读数条（声称 / 确认 / 待复核 / 信息增益轮），附录 A 标明「记录的是模型侧判定」；5 个附录编号、顺序、导出按钮、打印黑白全部保持。
- **配置页 03 剧本库**每张卡预告「确认 X · 证伪 X · 待复核 X」，让失败样本在演示动线的起点就能被指出来；`DEGRADED` 卡标为告警语义。
- 打印态新增元素统一白底黑字；四档视口（1440/1100/768/390）零溢出，移动端双轨降为 4×2，最小字号 11px。

### 5.3 三套剧本跑出来的真实结果（不是编的数字）

| 剧本 | 轮次 | AI 声称阳性 | 裁决确认 | 证伪 | 降级不确认 | 待复核 | 信息增益轮 |
|---|---|---|---|---|---|---|---|
| `CONVERGE_3` | 3 | 1 | 1 | 0 | 0 | 0 | R03 |
| `DEGRADED` | 4 | 1 | 0 | 1 | 2 | **3** | R04 |
| `NO_CONVERGE` | 8 | 0 | 0 | 0 | 0 | 0 | 无 |
| 越界（纯模拟） | 3 | 1 | 0 | 0 | 0 | 0（3 轮均不适用） | 无 |

`DEGRADED` 第 4 轮是最关键的一格：模型判 `VULNERABLE`、`confidence 0.91`、原文自证 `PASSED`，但标注集里该兜底算子**只绕过了 WAF 规则，点位未出现状态变化**，裁决为 `REFUTED`。这正是「AI 自动挖洞会算成功、我们不算」的现场证据。

## 8. 诚信边界：以下 4 项讲稿里仍要说「未做」

1. **真实 oracle 接入**：当前 `LAB-GT-01` 是预置演示标注；`HttpEngine.analyze()` 仍是未接入桩，真实判定路径不存在。
2. **误报率量化对照实验**：无真实标注集、无与「纯规则基线」共享响应样本的离线重判，不能声称「已量化降低误报率」。`docs/00` §6.9 仍为 P1。
3. **自建靶场与点位清单**：群聊里是设想，代码里只有 `SCOPE` 白名单与别名映射；ground truth 优势尚未兑现。
4. **按验证器置信度提前终止**：演示期仍是固定预算 + `hasHit` 终止，`MAX_ROUNDS` 未改成置信度门控。

> 本轮把 `docs/15` §5 里「声称 → 确认 → 证伪批量计数视图」从**未实现**推进为**演示机制骨架已跑通**，但上列 4 项没有变化。讲稿的「未做」清单按本节更新，不要因为新增了界面而多说一句「已验证」。
