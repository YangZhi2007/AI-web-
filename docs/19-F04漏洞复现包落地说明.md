# F-04 漏洞复现包导出 · 落地说明（v0.24.0）

> 需求来源：`AI漏洞智能探测系统新增功能需求说明书.docx` §4.4 / 表 9（R-04-01～05）/ 表 21 / §6.1 `/api/evidence/{id}/export` / §7.2 / §10.1。
> 本轮只做 F-04 一项；F-01～03、F-05～09 未实现，见本文 §7。

## 1. 需求原文与落地取舍

需求书写的是完整后端系统：接口返回压缩包下载地址、文件落盘、SHA-256 写入 `evidence_package` 表。本项目是**离线 `file://` 可运行、零外部请求、MockEngine 契约桩**的答辩演示控制台，仓库无服务端、无数据库、无依赖清单。本轮按项目既有边界落地为**浏览器本地生成的离线证据包**：

| 需求条目 | 原文要求 | 本轮落地 |
|---|---|---|
| R-04-01 | 仅命中可导出，其余拒绝并说明原因 | 仅独立裁决 `CONFIRMED` 且点位触发的轮次可导出；驳回/超时/越界/未攻破禁用并写明原因 |
| R-04-02 | 六类文件齐全 | 请求 / 载荷清单 / 响应回显 / 重放脚本 / 场景参数 / 核验摘要，逐一落盘 |
| R-04-03 | 命名含扫描编号与假设编号 | `<task_id>-H<轮次>-evidence.zip`，内部文件同名前缀 |
| R-04-04 | 单包 20 MB，超限截断并标注 | `CAP=20MB`，回显按字节截断，`06` 摘要 `truncation.applied=true` |
| R-04-05 | SHA-256 写入证据包表 | 整包 SHA-256 写入同名 `.sha256` 旁车文件 + `probe.evidencePack` 登记；包内 `06` 另存六类文件的逐文件哈希 |

刻意不做：`/api/evidence/.../export` 后端接口、`evidence_package` 数据库表、落盘路径。真实靶场重放执行器未接入，重放脚本做**离线完整性核对 + 裁决计数断言**，不发出任何请求。

## 2. 为什么「命中」用独立裁决判定

旧版若用 `hit_signal`（模型声称）当导出门禁，会把 v0.22 已抓出的那类误报当成可复现漏洞：`DEGRADED` 剧本 R4 模型判 `VULNERABLE`、置信度 0.91、原文自证 `validation:PASSED`，但实验前标注点位未触发，独立裁决为 `REFUTED`。本轮门禁只认 `oracle_verdict === 'CONFIRMED' && gt_triggered === true`，与需求书「判定权归靶场、结论字段不参与状态写入」一致。标准靶场 3 轮攻破可导出；加固靶场 8 轮未攻破、越界纯模拟均不可导出。

## 3. 实现结构

新增 `webapp/js/repro.js`（约 350 行，自实现、零依赖）：

- `sha256(u8)`：FIPS 180-4 同步纯 JS 实现。三组标准向量（`abc` / 空串 / `hello`）与 Node `crypto` 一致。
- `zipStore(files)`：store 模式（无压缩）标准 ZIP——本地文件头 + 中央目录 + EOCD，含 CRC32 表。系统 `unzip` / Python `zipfile` 均可解开。
- `buildFiles(r,rounds,cap)`：六类文件全部来自 report 真值；载荷清单只含 `OP_*` 编号白名单，不含任何载荷文本；请求文件剥离凭据。
- `buildPackage(r)`：打包 → 整包 SHA-256 → `.sha256` 旁车文件；**不把整包哈希写进包内**，避免「哈希依赖自身」的循环。
- `canExport(r)` / `exportRounds(r)`：导出门禁，只认独立裁决确认。
- `register(pack)` / `registry()`：点击导出后登记文件名、体积、SHA-256、任务与假设编号（对应表 21 的演示版）。
- `download(pack)`：ZIP + 旁车文件双下载，`Blob + a[download]`，零外部请求。
- `showReplay(pack)`：新窗口展示重放脚本；弹窗被拦截时退化为同页面板。
- `injectReportUI()` / `injectEvidenceUI()`：报告页工具条与证据链页结果卡注入入口，无报告/不可导出时显示原因。

接入点：`report.html`、`evidence.html` 各加一行 `<script src="js/repro.js" defer>`（位于 `console.js` 之后、`app.js` 之前）；`console.css` 新增「17b 复现包」样式段并在打印段隐藏复现 UI。**`console.js`、`app.js`、`api.js`、`core.css`、引擎、8 态状态机、5 附录契约零改动。**

## 4. 重放脚本做了什么

`04-replay.sh` 位于包内，两种模式：

- `--dry-run`：只打印本包声明（任务 ID、命中轮、标注集、确认/证伪计数、零外部请求），不检查文件、不发请求。
- 默认：从同包 `05-scenario.json` / `06-verification-summary.json` 读取真值，用 Node `crypto` 逐文件重算 SHA-256 并比对摘要，断言 `oracle_verdict === CONFIRMED` 的轮数等于摘要计数；有 `.sha256` 旁车与 `sha256sum` 时再核整包。任一不符退出码 1。

实测输出：`[replay] 结果：六类文件哈希一致 · 裁决确认 1 轮可复现 · 与摘要结论一致`，整包 `OK`。这是**可核对的离线重放**，不是对真实靶场的利用链重放。

## 5. 视觉方向（unslop）

- 产品：把攻击结论转成可离线核对的归档证据包，给答辩评审当场验真。
- 性格：精确、克制、可被检查。
- 世界：档案柜与封条——卷宗刻度语言延续报告页。
- 记忆点：导出后的档案封条行（文件名 / 截断哈希 / 重放按钮三栏），长哈希只显示首尾、完整值在同包 `.sha256` 与登记里。
- 签名细节：工具条上安静的 11px 等宽规格标签 `6 文件 · SHA-256 · 离线重放`；PDF 仍是唯一亮色主按钮。
